# 左侧面板 Tab 拥挤问题：方案探索结论（README）

> 多 agent 工作流：3 方案代理并行设计 → 2 评委代理独立打分 → 冠军方案落地为可交互原型。
> 原型：`prototypes/sidebar-S3.html`（浏览器直接打开，或 `python -m http.server 9877` 后访问）。

## 评审结论

| 排名 | 方案 | 评委 A（架构/可扩展） | 评委 B（工程落地/交互体验） | 结论 |
|---|---|---|---|---|
| 🥇 | **S3 可滚动分组 + 置顶收藏** | 8.05 | 7.90 | **冠军**（两评委一致） |
| 🥈 | S2 双层导航 | 7.85 | 7.85 | 分组逻辑最严密，但契约改动面最大 |
| 🥉 | S1 溢出收纳 | 6.85 | 7.60 | 实现最轻，但只解决「放得下」不解决「找得到」 |

**两评委一致的落地前置条件**：
1. 消除双入口歧义：左侧 = 全局面板导航，右侧 = 当前面板内容；激活态上提为单一权威。
2. 持久化统一走 `cap.config`（而非 localStorage 直写）。
3. 吸收 S1 的容量自适应思路（高度不足时优先隐藏低频项而非挤压）。

## 冠军方案核心（S3）

- 侧栏纵向四段：品牌（固定）→ 置顶区（固定，横排图标块，上限 8）→ 分组滚动区（唯一滚动容器，分组可折叠）→ 会话列表（固定底部）。
- 多面板数量增长只增加纵向滚动长度，**结构性消灭横向挤压**；置顶区保证高频入口始终可见。
- 状态持久化：`polaris.sidebar.prefs.v1`（pins / collapsedGroups / active）。

## 原型已验证的交互闭环

1. 置顶/取消置顶（☆ 与右键/长按）。
2. 分组折叠/展开（含激活面板所在分组强制展开）。
3. 激活面板切换（分组内条目与置顶区图标块联动）。
4. 移动端 ≤768px 抽屉化 + 选中即收抽屉。
5. 13 个示例面板（4 分组 + misc）不挤压。

## 落地到宿主（后续工作，不在本次范围）

- `SlotLayout.tsx`：sidebar 槽内、`<SlotOutlet slot="sidebar"/>` 之前挂载 `<SidebarNav />`。
- `types.ts`：`SlotDescriptor` 增加可选 `group` / `icon`。
- 持久化改走 `cap.config`；吸收 S1 容量自适应与 S2 激活态单一权威。

## 原型迭代 v2（参考 Polaris ToolSwitcher 信息密度）

用户要求参考 Polaris 顶部工具（ToolSwitcher）。已重做原型 `prototypes/sidebar-S3.html`，对齐其高密度模式：

- 顶部搜索框（按名称/id 过滤，含分组级过滤）。
- 置顶区：4 列 icon+短名 grid（对齐 ToolSwitcher 的 pinned grid）。
- 分组列表：分组头（名 + 计数）+ 条目行（icon + 名称 + ☆置顶钮）。
- 底部「当前面板 + 登出」栏（对齐 ToolSwitcher 的 activeSidebar 底栏）。
- 会话列表压缩到底部小区域，导航占主体——信息密度显著高于 v1。

已验证交互闭环：搜索过滤、置顶/右键取消、分组折叠展开、激活切换、空组隐藏、misc 兜底恒在。
