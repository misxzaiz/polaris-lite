# 左侧面板 Tab 拥挤问题：多 agent 方案探索总纲（brief-sidebar）

> 背景：polaris-lite 左侧为「图标栏 + 会话列表」结构。随着面板插件增多，图标栏 tab 会挤压变形（溢出、换行、无法点击）。需要多 agent 工作流产出一个**合理的原型方案**（不直接实施到宿主）。

## 现状问题

1. 图标栏（sidebar 前列的 tab 条）数量随插件线性增长，超过宽度后挤压/溢出。
2. 移动端（≤768px）侧栏变抽屉后，tab 仍会挤压。
3. 无分组/折叠/收纳机制，新增面板只能继续加 tab。

## 目标

产出一个**可交互 HTML 原型**（单文件，浏览器直接打开），演示左侧面板在「多插件」场景下的合理交互方案，并配一份设计说明。不要求接入宿主源码。

## 硬性要求

1. 原型必须演示 ≥10 个面板时的形态（构造 10+ 个示例面板）。
2. 至少包含：图标栏（或等价导航）+ 会话列表区 + 面板内容区三段结构（对齐现有布局）。
3. 方案需说明：新增面板如何收纳、溢出如何降级、移动端抽屉如何表现。
4. 多 agent 工作流：3 个方案代理并行设计不同路线 → 2 评委评审 → 冠军方案落地为原型。

## 三条路线（3 个方案代理各认领一条）

| # | 代号 | 核心思路 |
|---|------|----------|
| S1 | 固定图标栏 + 溢出收纳 | 图标栏固定宽度，超出部分收进「更多」菜单（⋮），点击弹出抽屉列出剩余面板 |
| S2 | 双层导航 | 第一层大分类（如：对话/开发/数据/工具），第二层才是该分类下面板；点击分类展开二级列表 |
| S3 | 可滚动分组 + 置顶收藏 | 图标栏可纵向滚动，按分组分段；常用/收藏置顶，其余按分组折叠；支持拖拽排序（原型可简化为点击置顶） |

## 评分维度（2 评委）

- A 信息架构合理性 40%（多面板时查找效率、分组逻辑、可扩展性）
- B 交互体验 30%（点击成本、可视性、移动端表现、状态保持）
- C 实现可行性 20%（原型能否直接指导宿主实现，改动面）
- D 视觉与一致 10%（与现有深色主题/布局协调）
