# 左侧面板导航方案评审 · judging.md

> 评审背景：`docs/sidebar-schemes/brief-sidebar.md`（左侧 Tab 拥挤问题，三方案并行探索）。
> 本文件为**评委 A** 的评审记录。视角：**信息架构与可扩展性**（多面板查找效率、分组逻辑、可扩展性优先）。
> 评分维度与权重：A 信息架构合理性 40% · B 交互体验 30% · C 实现可行性 20% · D 视觉与一致 10%；1–10 分，0.5 步进。
> 评审依据：三份方案文档 + 现有代码核对（`src/core/SlotLayout.tsx`、`SlotOutlet.tsx`、`types.ts`、`slotRegistry.ts`、`src/styles.css`）。

## 一、S1 · 固定图标栏 + 溢出收纳（`S1-overflow-menu.md`）

### 得分表

| 维度 | 权重 | 得分 | 加权 |
|---|---|---|---|
| A 信息架构合理性 | 40% | 6.0 | 2.40 |
| B 交互体验 | 30% | 6.5 | 1.95 |
| C 实现可行性 | 20% | 8.5 | 1.70 |
| D 视觉与一致 | 10% | 8.0 | 0.80 |
| **加权总分** | | | **6.85** |

### 评语

- **A（6.0）**：结构上彻底消灭溢出（图标栏宽度恒定、容量按高度裁剪、其余进「更多」），可扩展性是「无限收纳」型的。但信息架构本质仍是**无分组的平面列表**：12+ 面板时可见区只剩若干无文字图标，被收纳面板只能进浮层**线性扫描**；图标语义不清时（方案自己也承认首字母块辨识度下降）查找效率随面板数线性劣化。没有分组/分类维度，是三条路线里 IA 最弱的。
- **B（6.5）**：可见图标 1 击直达；「激活钉住」（pinned-active，被收纳的激活面板提升到可见末位 + ⋮ 挂 badge）是很好的状态保持设计，保证正在用的面板永远可见。但访问任一非可见面板需要「开浮层 → 视觉扫描 → 点击」三步，且浮层内条目多时仍会内滚。移动端 action-sheet + 安全区处理到位。容量抖动（ResizeObserver 临界跳变）方案已给出滞回对策，意识好。
- **C（8.5）**：三条路线中**改动面最小**：纯壳层展示裁剪，不改 cap 总线、不改插件契约（`SlotDescriptor` 仅可选加 `icon`）、插件零改动；对 `SlotLayout`（侧栏改双列、插 `SidebarIconBar`）、`SlotOutlet`（activeIdx 上提为受控）的对接点写得具体，回归点（激活态双源）也点得很准。原型可直接指导宿主实现。
- **D（8.0）**：48px 竖向图标栏是成熟范式，token 全部沿用（`--accent-soft`、`--border` 等），激活指示条与现有 `.chat-session-item.active` 语言一致。

### 最大缺陷

**平面图标 + 溢出收纳没有解决「查找效率」问题，只解决了「放得下」问题。** 面板越多，浮层越长、图标越难辨认；无分组维度意味着扩展性只是「容量的扩展」而非「检索的扩展」。若采纳，建议至少补：浮层内按分组分节 + 面板名过滤输入，否则 10+ 面板时体验会明显退化。

## 二、S2 · 双层导航（`S2-two-level-nav.md`）

### 得分表

| 维度 | 权重 | 得分 | 加权 |
|---|---|---|---|
| A 信息架构合理性 | 40% | 8.5 | 3.40 |
| B 交互体验 | 30% | 7.5 | 2.25 |
| C 实现可行性 | 20% | 7.0 | 1.40 |
| D 视觉与一致 | 10% | 8.0 | 0.80 |
| **加权总分** | | | **7.85** |

### 评语

- **A（8.5）**：三方案中**分组逻辑最严密**：一级固定四分类（对话/开发/数据/工具）保证一级结构恒定可预期，查找复杂度从 O(n) 降为「扫 4 个分类 + 单分类内短列表」；未声明 `category` 一律落 `tool` 兜底、dev 模式挂「未分类」徽标，保证新面板永不丢失且倒逼声明；计数徽标 + 单开手风琴控制纵深。可扩展性明确承诺「面板增长不影响一级结构」，并对「分类膨胀 >6」的边界如实交代（届时合并分类或叠加 S1 收纳）。扣分点：单分类内面板过多（>15）时只有排序 + 预留过滤位，v1 没有分类内检索的完整设计。
- **B（7.5）**：二级条目**带文字名称**，可发现性远好于 S1 的纯图标；点击二级条目才切换激活（浏览分类无副作用）语义干净。但到达一个面板典型要 2 击（展开分类 + 点条目），单开模式下跨分类对比需反复收展，有一定点击成本；激活分类自动展开的细节方案未明确写（只写了默认展开当前激活项在移动端，桌面端建议补齐）。移动端复用现有抽屉 + 点击即收，状态经 `cap.config` 持久化，跨会话记忆，处理完整。
- **C（7.0）**：改动面三者最大：`SlotDescriptor` 加 `category`（**契约变更**，需同步插件仓样例）、`slotRegistry` 加 `listByCategory` + `onChange` 订阅（现有 registry 是静态快照，无通知）、新建 `panelNavStore` + `PanelNav`、`SlotOutlet` 激活态受控化（保留回退分支）。好处是方案把每一步的兼容路径都写清了（无导航时退回现有 tab 行为、会话列表两种共存形态二选一），风险清单质量高；但「会话列表与对话分类的_space 争用」尚未定稿（6.3 留了 a/b 两案），落地前仍有一处设计决策悬置。
- **D（8.0）**：全部使用既有 token，激活态与 `.chat-session-item.active` 的 `--accent-soft` + accent 边语言一致，无新色彩体系。

### 最大缺陷

**为获得最优分组 IA，付出了三者中最大的契约与实现代价，且「会话列表归入对话分类」的 IA 融合尚未定稿。** `category` 是对插件 manifest 契约的扩展，所有插件需要补声明（不补则集中落工具分类，初期「工具」会偏长）；若能像 S3 一样用「manifest 可选声明 + 内置映射兜底」且不动 `SlotOutlet`，性价比会更高。

## 三、S3 · 可滚动分组 + 置顶收藏（`S3-scroll-groups.md`）

### 得分表

| 维度 | 权重 | 得分 | 加权 |
|---|---|---|---|
| A 信息架构合理性 | 40% | 8.5 | 3.40 |
| B 交互体验 | 30% | 8.0 | 2.40 |
| C 实现可行性 | 20% | 7.5 | 1.50 |
| D 视觉与一致 | 10% | 7.5 | 0.75 |
| **加权总分** | | | **8.05** |

### 评语

- **A（8.5）**：与 S2 同级的分组 IA（语义分组 + `misc`「更多插件」兜底永不丢失 + 空组隐藏 + 组内确定性排序 order→lastUsedAt→name），并在此之上**叠加了频率维度**：置顶区（上限 8，独立固定不滚动）让高频面板 1 击直达且永不挤出视口，直接回应了 brief 痛点 1/3。纵向唯一滚动容器吸收面板增长，可扩展性与 S2 同级、明显优于 S1。扣分点：置顶（用户态）+ 分组（系统态）双机制并存，侧栏信息层级比 S2 多一层，规则更多（置顶满额、取消回组、空组隐藏、激活强制展开），用户需要理解的模型更复杂。
- **B（8.0）**：常用面板 1 击、其余 2 击，与 S2 持平但高频路径更短；折叠默认态（仅展开置顶过/激活所在分组）控制首屏噪声；「激活面板所在分组强制展开」保证激活态永远可见，状态保持设计最完整（pins/collapsed/lastUsed 全持久化）。移动端细节最扎实：触摸目标 ≥40/44px、长按取消置顶（含移动误判防护）、选中即收抽屉、`overscroll-behavior: contain`。扣分点：置顶管理本身有操作成本（星标切换、长按/右键取消），低频用户可能从不使用置顶，却要面对多出来的置顶区视觉段。
- **C（7.5）**：对宿主的侵入介于 S1 与 S2 之间且**不动 `SlotOutlet`**（只读 `host.slots.list('panel')` 现成 API）、`slotRegistry` 零改动、`SlotDescriptor` 仅加可选 `group`/`icon`（向后兼容）；新增 `SidebarNav` + `sidebarPrefs` 两个内聚文件，四槽布局壳与抽屉机制完全复用。方案对滚动穿透、localStorage 容错、长按与滚动冲突等实现风险都有预判。两处扣分：① 右侧 panel 槽 tab 栏保留 → **双入口歧义**（在哪切面板）只给了「视觉弱化」的软对策；② 持久化用 localStorage 而非宿主 `cap.config`，与 S2 的持久化路线不一致，落地时需统一。
- **D（7.5）**：token 全复用、断点对齐现有 768px/360px；但侧栏纵向四段（品牌/置顶/分组/会话）在 260px 宽、矮窗口下挤压感比 S1/S2 的两段式更明显，置顶图标横排块也略破坏侧栏原有的单列节奏。

### 最大缺陷

**左侧全局面板导航与右侧 panel 槽 tab 栏并存，形成「两个地方都能切面板」的双入口歧义**——这在多面板场景下恰恰是要治理的核心困惑；方案只承诺「视觉上弱化右侧 Tab」，没有给出唯一的激活权威（S1/S2 都明确了激活态上提为单一权威）。另外 localStorage 持久化与宿主 `cap.config` 体系不一致，落地前需收敛。

## 四、排名与冠军推荐

| 排名 | 方案 | 加权总分 | 一句话结论 |
|---|---|---|---|
| 🥇 1 | **S3 可滚动分组 + 置顶收藏** | **8.05** | 分组 IA 与 S2 同级，叠加「常用 1 击直达」，且不动 `SlotOutlet`、契约只加可选字段，性价比最高 |
| 🥈 2 | S2 双层导航 | 7.85 | 分组逻辑最严密、契约最干净，但实现改动面最大，且会话列表融合方案未定稿 |
| 🥉 3 | S1 固定图标栏 + 溢出收纳 | 6.85 | 实现最轻、最稳，但只解决「放得下」不解决「找得到」，IA 上限最低 |

### 冠军推荐（评委 A）

**推荐 S3 作为冠军方案**，理由从信息架构与可扩展性出发：

1. **查找效率三维覆盖**：系统分组（语义扫描）+ 置顶区（频率直达）+ 兜底 misc（新面板永不丢失），是三方案中唯一同时覆盖「按类找」与「按频找」的；brief 明确要求「常用/收藏置顶」，S3 是唯一把该要求做成一等公民的方案。
2. **可扩展性真实成立**：面板增长只增加唯一滚动容器（`.s3-groups`）的纵向长度，一级结构（置顶区 + 分组头）不随面板数变化；对比 S1 的浮层线性扫描，检索效率不随规模劣化。
3. **落地代价可控**：四槽布局与抽屉机制零改动、`slotRegistry` 零改动、`SlotOutlet` 零改动（对比 S2 需要受控化改造 + registry 加订阅），契约仅增可选字段，渐进采用（不声明落 misc）。

### 落地前置条件（采纳 S3 需先解决）

1. **消除双入口**：明确 `activePanelId` 单一权威（建议仿 S1/S2 上提为共享 store），右侧 panel 槽 tab 栏降级为当前面板内容头或直接移除，避免「两处切面板」。
2. **持久化通道统一**：`SidebarPrefs` 落地时改走 `cap.config`（或明确 localStorage 仅限原型），与宿主配置体系一致。
3. **吸收 S2 的契约优点**：`group` 字段的声明规范可参考 S2 的 `category` 设计（含 dev 模式「未分类」徽标提示），并同步插件仓样例。
4. **吸收 S1 的容量纪律**：置顶区上限 8 + 空组隐藏已是好设计，可再参考 S1 的滞回思路处理折叠展开的临界抖动。

## 一、S1 · 固定图标栏 + 溢出收纳

| 维度 | 权重 | 得分 | 加权 |

| A 信息架构合理性 | 40% | 7.5 | 3.00 |
| B 交互体验 | 30% | 7.0 | 2.10 |
| C 实现可行性 | 20% | 8.5 | 1.70 |
| D 视觉与一致 | 10% | 8.0 | 0.80 |

**评语**：
- **A（7.5）**：固定 48px 竖栏 + 常驻「更多 ⋮」从结构上根治横向挤压，容量随高度自适应、宽度恒定不换行；但本质仍是平面列表，无分组语义，面板一多全堆进浮层线性扫描，可发现性随规模衰减。钉住激活（pinned-active）规则聪明，但会让面板在「可见/收纳」间跳位，位置记忆不稳定。
- **B（7.0）**：可见面板一键直达、激活项永不失联（badge 提示 + 浮层高亮）；但点击被收纳面板需「开浮层→按图标/名查找→点击」三步，图标无文字时 12+ 面板辨认成本高。移动端 action-sheet + 安全区处理得当；容量抖动的滞回对策考虑周全。
- **C（8.5）**：**三案改动面最小**：纯展示层裁剪，不改注册表结构、不改插件契约（icon 可选）、不改 cap 总线；ResizeObserver 容量计算 + 首帧保守渲染 + 浮层挂 shell 根层级规避 `isolation: isolate` 裁剪，工程细节完整。唯一硬点是激活态双源收敛（图标栏 vs `SlotOutlet` 内部 state），文档已定位为首要回归点并给出 context/store 方案。
- **D（8.0）**：48px 图标栏 + accent 指示条 + `--accent-soft` 激活块，与现有深色主题语言一致，成熟范式无跳脱。

**最大缺陷**：平面图标 + 收纳浮层没有分组/检索能力，只解决「放得下」不解决「找得到」；面板规模上去之后「更多」浮层会退化为新的拥挤列表，且钉住换位使同一面板入口位置不稳定，损害肌肉记忆。

| 维度 | 权重 | 得分 | 加权 |

| A 信息架构合理性 | 40% | 8.5 | 3.40 |
| B 交互体验 | 30% | 7.5 | 2.25 |
| C 实现可行性 | 20% | 7.0 | 1.40 |
| D 视觉与一致 | 10% | 8.0 | 0.80 |
| **加权总分** | | | **7.85** |

**评语**：
- **A（8.5）**：三案中结构化程度最高：O(分类数×组内条目) 替代 O(n) 平面列表，一级恒定 ≤4 行，面板增长被隔离在二级；插件自声明 `category` + `tool` 兜底保证「新面板永不丢失」，dev 模式未分类徽标是很好的治理钩子；展开状态与激活 id 持久化到 `cap.config`。扣分点：分类由宿主写死、插件不可新增语义分类；「对话」分类同时装会话列表与面板的特例映射略显别扭（文档 6.3 亦留了待定项）。
- **B（7.5）**：层级清晰、默认单开控制纵向空间，二级条目带文字名称可发现性好；但跨分类跳转需两次点击（先展开分类再点面板），单开模式下无法一眼纵览全部面板，探索性浏览弱于 S3 的置顶区。
- **C（7.0）**：改动面三案最大：契约扩展（`category`）+ registry 聚合与 `onChange` 订阅 + 新 store + 新组件 + `SlotOutlet` 受控化 + 现有插件 manifest 补声明，跨 7 类文件，落地周期最长。好处是激活态单一权威（`panelNavStore`）设计最干净，「无分类时退化现有 tab」的回退路径明确。契约变更需同步插件仓样例，协调成本高。
- **D（8.0）**：全部使用既有 token，激活态语言与 `.chat-session-item.active` 一致，`role="tree"/treeitem"` 语义到位。

**最大缺陷**：宿主写死的固定分类不可扩展，跨分类访问面板固定两次点击；且方案自认「治面板多、不治分类多」——分类一旦膨胀仍需回头叠加 S1 的收纳或 S3 的置顶，架构上留了后手依赖。

**评语**：
- **A（8.0）**：「系统分组 + 用户置顶」双层结构兼顾可扩展性与高频直达：分组管发现、置顶管效率，`misc` 兜底组保证不丢面板；组内 order→lastUsed→name 确定性排序避免渲染跳动；唯一滚动容器吸收面板增长。扣分点：置顶（上限 8）与分组两套机制并存，用户要学的模型比 S2 多一层；misc 组可能成为新的堆场。
- **B（8.0）**：**三案中高频使用体验最好**：常用面板置顶一键直达、激活面板所在分组强制展开（状态永不丢）、置顶区与会话列表始终可见；折叠持久化 + 移动端长按取消（含误判防护）+ 选中即收抽屉的细节完整。代价是低频用户也要面对多出来的置顶区与「置顶/折叠」两个新操作。
- **C（7.5）**：对接面干净：`SlotOutlet` **零改动**（只读 `host.slots.list`），`SlotLayout` 仅插入一个组件，四槽壳与抽屉机制不动；`group/icon` 为可选字段渐进采用。扣分点：① 激活态上提问题被回避——右侧 `slot-tabbar` 与左侧导航双入口并存，文档只给「视觉弱化」软对策，落地时仍要补 SlotOutlet 受控化改造，风险后置；② 持久化走 localStorage 而非 `cap.config`，与宿主数据纪律存在分叉；③ 长按手势与滚动冲突需实测。
- **D（8.0）**：四段式侧栏（品牌/置顶/分组/会话）复用全部主题 token，断点对齐现有 768px/360px，视觉无跳脱；矮窗口下四段略挤但可接受。

**最大缺陷**：**双入口歧义未闭环**——左侧新导航与右侧 panel 槽 `slot-tabbar` 并存，激活态权威没有像 S2 那样明确上提为单一 store，落地前必须补一次 `SlotOutlet` 受控化；且 localStorage 直连持久化绕开 cap 总线，多端/多实例场景状态不同步。

## 四、排名与冠军推荐（评委 B）

| 排名 | 方案 | 加权总分 | 一句话定位 |
|---|---|---|---|
| 🥇 1 | **S3 可滚动分组 + 置顶收藏** | **7.90** | 体验最完整、侵入最小，分组+置顶同时解决「发现」与「直达」 |
| 🥈 2 | S2 双层导航 | 7.85 | 信息架构最正统、最扛增长，但落地成本与点击成本最高 |
| 🥉 3 | S1 溢出收纳 | 7.60 | 工程成本最低的止血方案，但信息架构未升级，问题被延迟 |

### 冠军推荐（评委 B）

**推荐 S3 作为冠军方案**，从工程落地与交互体验出发：

1. **唯一同时覆盖「按类找」与「按频找」**：分组解决可发现性，置顶区解决高频直达，且激活分组强制展开保证状态不丢——S1 有直达无分组，S2 有分组无直达。
2. **对现有代码侵入最小**：`SlotOutlet` 与 `slotRegistry` 零改动、四槽壳与抽屉机制零改动、契约仅加可选字段渐进采用；对比 S2 的七文件改造，S3 可在一个迭代内落地。
3. **移动端细节最扎实**：触摸目标、长按误判防护、选中即收抽屉、overscroll 约束均已预判，原型可直接指导实现。

**落地前提（与评委 A 结论一致的两条硬前置）**：

1. **激活态单一权威**：把 `activePanelId` 上提为共享 store（如 `panelNavStore`），`SlotOutlet` 改受控激活并保留内部 state 回退；右侧 `slot-tabbar` 在导航接管后弱化为当前面板内容头或移除，消除双入口歧义。
2. **持久化对齐宿主纪律**：`pins/collapsedGroups` 优先走 `cap.config`（namespace `sidebar-nav`），localStorage 仅作无 cap 环境降级。

**吸收另两案的建议**：采纳 S1 的容量自适应（极矮窗口下置顶区收缩、超限项回落分组首位，ResizeObserver + 滞回）；分组声明字段与 S2 的 `category` 语义互通（内置映射表兜底），未来升级严格双层导航时插件无需二次改造。

一句话结论：**S3 为主干，嫁接 S2 的激活态治理与 S1 的容量自适应，即「S3.5」为最终落地形态。**
