# 输入框会话操作带：新增对话 + 左右切换会话 规划（chat-input-session-nav）

> 需求：AI 对话**输入框**支持「新增对话」，并支持「左右切换会话」。
> 本文是**纯规划**（用户明确只要方案不要实施），含现状分析、方案对比、推荐与实施拆解。
>
> 归属：polaris-lite 的 `chat-lite` 插件（输入区 `input` 槽的 `ChatInput` 组件）。
> 纯插件改动，**宿主零改动**。

## 一、需求解读

用户在**输入框里**（而不是去左侧栏）完成两件事：

1. **新增对话**：输入框附近一键开新会话，光标自动就位即可输入——消灭「绕到左侧栏点 + 号」的路径；
2. **左右切换会话**：在最近会话之间快速往返（上一个 / 下一个），类似浏览器 tab 或聊天软件的快速切换——高频场景是「边干活边在 2~3 个会话间横跳」。

体验红线（需求原话「需要特别考虑用户体验」的精神延续）：
- 切换/新增**不丢任何东西**：草稿（per-session 已有）、附件、待发队列、流式回复；
- **不打断流式**：当前会话在生成时切走，回复继续落在原会话（store 已天然支持，UI 只切 activeId）；
- 移动端（≤768px）同样可用；
- 键盘用户有等价路径。

## 二、现状（代码事实，全部实测核对）

- 输入区：`plugins/chat-lite/ChatInput.tsx`（621 行），位于 `input` 槽。输入条
  `chat-input-bar`（max-width 840px 居中）内含：警告条 → 附件条 → textarea → 助手抽屉 →
  **按钮行 `chat-input-btns`**（附件 / 调谐 / 工作目录 chip / 提示语 / ContextMeter / 停止/发送/排队）。
- 会话状态：`store.ts` zustand `useSessionStore`——`sessions[]`（**新会话插在数组头部**，
  即 sessions[0] 是最新）、`activeId`、`createSession()`、`setActive()`；持久化 localStorage
  `chat-lite.sessions.v1`（防抖 800ms + 1.5MB 容量裁剪，从最旧会话丢起）。
- 现有「新增会话」入口只有左侧栏 `SessionSidebar` 的 `chat-session-new` 按钮；
  「切换会话」也只能在侧栏点条目。
- **流式与切换天然解耦**：消息写入按 `sessionId` 寻址（appendMessage/updateMessage），
  切换只改 `activeId`，不触碰消息流。流式回复落原会话，切走再切回不丢。
- **草稿已是 per-session**：`sessionStorage chat-lite.draft.<id>`，切换时防串（取消在途防抖）。
- **待发队列 per-session**：`pending[sessionId]`，内存态不落盘，切走继续留存。
- 输入框键盘已有三级语义：↑↓ 历史召回（空输入/浏览态才接管）、Enter 发送、
  ESC 关浮层→清空→中断。**尚无 ←→ 会话切换**。
- 已知耦合点：切换会话时 `ChatInput` 的 effect 会取消在途草稿写入并载入新草稿——
  新增「按钮切会话」复用同一 effect，零额外处理。

## 三、方案对比

| # | 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|---|
| A | 按钮行加「新对话」按钮 + Alt+←/→ 键盘切换 | 输入条按钮行两枚图标钮（+、⇆） | 实现最轻；不占新空间；键盘免坐标 | 可见性弱：不点开按钮行不知道能切 |
| B | 输入条顶部会话 chip 条 | textarea 上方横排最近 N 个会话 chip（当前高亮，点选切换，尾端「+ 新对话」） | 一眼可见当前/相邻会话；点击直达；信息密度可控 | 输入条增高 ~34px；chip 与左侧栏功能重复感 |
| C | textarea 上方一条「会话切换行」：‹ 上一个 · 标题 · 下一个 › | 类分页器，只显示相邻会话 | 极简、永不拥挤；左右语义与需求措辞完全一致 | 只能逐个跳，不能直达任意会话（但侧栏已有全量列表） |
| D | 输入框聚焦时 Alt/⌘+K 弹会话命令面板 | 命令面板列出全部会话搜索切换 | 最强（任意跳+搜索） | 面板实现重；移动端无键盘优势归零 |
| E | 手势滑动（消息区左右滑切会话） | 触屏手势 | 移动端爽 | 桌面无手势；与消息区横向滚动/选择文本冲突；误触风险高 |

**推荐：A + C 组合（分阶段），B 作为 C 的增强可选项。**

- 第一期（核心）：**按钮行「＋ 新对话」按钮 + 输入条顶部「‹ ›」相邻切换行 + Alt+←/→ 快捷键**。
  理由：C 的「左右」与需求措辞严格对齐且永不拥挤；A 的 + 按钮满足「新增对话」；
  Alt+←/→ 给键盘与效率用户；三者共享同一套 `goPrev/goNext/goNew` 纯函数。
- 第二期（可选增强）：切换行中间标题点击展开 B 的 chip 条（全量最近会话直达）。
  D/E 不推荐：D 重、E 误触且桌面无效。

## 四、目标形态（推荐组合）

```
┌──────────────────────────────────────────────┐
│ ‹  上一会话   │ 当前会话标题 ▾ │ 下一会话 ›   │  ← 会话切换行（仅 sessions>1 时出现）
├──────────────────────────────────────────────┤
│  [附件条]                                     │
│  textarea …                                   │
│  [📎][🎚][目录chip]  hint  ◔  [＋新对话][发送] │  ← 按钮行（新增「＋新对话」）
└──────────────────────────────────────────────┘
键盘：Alt+← 上一个 · Alt+→ 下一个 · Alt+N 新对话（textarea 聚焦时；IME 组词中不接管）
```

体验细节（UX 硬指标）：
1. **切换行只在 >1 个会话时出现**——单会话不显示空切换器（避免「按了没反应」的困惑）；
2. **到头即停 + 视觉弱化**：已是最新会话时 › 半透明禁用；最旧时 ‹ 半透明禁用；
   不做循环（循环会让人迷失「现在在第几个」）；
3. **流式中切换不锁**：当前会话生成中照样可切；切走后原会话流式继续落盘；
   切换行对生成中的会话标题加一个 2px 呼吸点（状态可见）；
4. **切换后焦点回 textarea**、载入该会话草稿（既有 effect 已做）、历史浏览态复位；
5. **新增会话即聚焦**：点「＋新对话」→ 建会话 → textarea focus + 光标在行尾；
   空会话防重复：当前会话已是空会话（0 条消息）时点 + 不再新建，只聚焦
   （避免连点产生一堆空壳会话——侧栏现有 + 按钮无此防护，规划中一并修）；
6. **标题显示**：沿用侧栏规则（`title !== '新会话'` 用 title，否则取首条消息前 18 字），
   中间标题可点击 → 展开第二期 chip 列表（第一期先做 tooltip 全名）；
7. **a11y**：‹ › 为 `role=button` + `aria-label="上一个会话/下一个会话"`，
   切换行容器 `aria-label="会话切换"`；快捷键在 textarea 的 onKeyDown 里接
   （Alt 组合键不与 IME/输入法冲突；`e.nativeEvent.isComposing` 先行短路）；
8. **移动端**：切换行同样显示（高度 30px 更紧凑）；按钮行已有 min-height 42px 预算，
   ＋新对话用纯图标 40px 方钮（与 attach/tune 同规格），不挤占发送按钮（flex: 0 0 auto 已保证）。

## 五、实现拆解（后续实施用，本次不做）

### 1. store 层（store.ts，+30 行）
- 新增选择器 `sessionOrder()`：`sessions` 已是「最新在前」，相邻切换 = 数组下标 ±1；
  无需新状态。
- `createSession` 增加防重复语义：调用方判断当前 active 会话 `messages.length === 0`
  时不新建只聚焦（放 UI 层判断即可，store 不动）。

### 2. 纯函数层（新增 `sessionNav.ts`，~40 行，可单测）
```ts
// 输入：sessions 数组 + activeId；输出：{prev, next, canPrev, canNext}
// prev = 下标+1（更旧），next = 下标-1（更新）——「← 往回翻历史，→ 往最新走」
export function neighbors(sessions, activeId): NavInfo
```
- 单测：空/单会话/到头/普通中间四种形态（进 `tests/` 或插件内测；lite 现无插件级测试
  文件，可挂到 `tests/core.test.mjs` 同目录新建 `tests/session-nav.test.mjs`，
  纯函数零依赖可直接 node:test）。

### 3. UI 层（ChatInput.tsx，+80 行；新建 `SessionNav.tsx` ~90 行）
- `SessionNav`：渲染在 textarea 与附件条之间（`chat-input-bar` 内、附件条上方）；
  sessions>1 才渲染；‹ 标题 › 三段；生成中会话呼吸点；
- 按钮行：在 ContextMeter 前插入「＋新对话」方钮（与 attach/tune 同 class 规格）；
  当前会话为空壳时按钮只聚焦不新建；
- 键盘：`onKeyDown` 顶部增加 Alt+←/→/N 分支（isComposing 短路；Alt+N 需 `e.preventDefault()`
  防止浏览器_focus 搜索框等默认行为）；
- 切换动作统一走 `setActive(id)`——草稿载入、历史态复位、焦点管理全部复用既有 effect。

### 4. CSS（chat-input.css，+45 行）
- `.chat-session-nav`（切换行）：高 30px、居中、`color: var(--text-faint)`、hover 变亮；
  禁用态 opacity .35；生成中呼吸点用 `--accent` 2px 圆点 + 1.6s 呼吸动画
  （`prefers-reduced-motion` 下静态）；
- `.chat-session-new-inline`：40px 方钮，规格对齐 `.chat-send.attach`；
- 窄屏（≤768px）：切换行高 28px、标题最大宽 40vw ellipsis。

### 5. 验收清单
- 多会话：‹ › 逐个切换正确（方向语义：→ 更新 / ← 更旧）、到头禁用；
- 切换后：草稿正确载入不串、附件/队列/流式不丢、焦点在 textarea；
- 流式中切走：原会话继续生成，切回时消息完整；
- 新增：点按钮/Alt+N 建会话并聚焦；当前空会话时防重复；
- 单会话/零会话：切换行不渲染；空态（no-session）下发送仍自动建会话（既有逻辑）；
- 移动端 390px：切换行不溢出、＋按钮可点；
- `typecheck` + 既有 `npm test` 全绿 + 新增 session-nav 单测。

## 六、风险与边界

- **纯插件改动**：全部落在 `plugins/chat-lite/`，不触碰宿主 core；无 cap/manifest 变化
  （不新增能力声明），构建走既有 `build-plugins.mjs` 流程；
- **会话顺序语义**：依赖「sessions[0] 最新」这一既有不变量（createSession 头插 +
  deleteSession 保序 + 持久化原样恢复）。若未来引入拖拽排序/置顶，`neighbors` 需改为
  按 `createdAt` 排序的独立口径——在 sessionNav.ts 里把排序收口成单一函数即可；
- **Alt+←/→ 与浏览器历史键冲突**：textarea 聚焦时 preventDefault 可拦；但 Firefox 的
  Alt+← 在部分平台先于页面处理——规划中把 Alt 组合定为「尽力而为」，核心路径是点击；
  若实测被浏览器吃掉，回退方案是 Ctrl+←/→ 或 [ ] 方括号键；
- **与左侧栏的职责边界**：输入框切换行只做「相邻快速横跳」，全量浏览/搜索/删除/工作区
  设置仍归侧栏——不把侧栏搬进输入条，避免功能重复与视觉过载；
- **流式中新建会话**：允许（新会话独立流），与 Polaris 主行为一致；不阻断。

## 七、明确不做（本期）

- 会话拖拽排序 / 置顶（侧栏已有序，切换行不承载）；
- 会话搜索（侧栏/二期 chip 层再说）；
- 消息区滑动手势切换（误触风险）；
- 多窗口/多 tab 会话同步（localStorage 单写者模型不支持，lite 形态不扩）。
