# 文件浏览器 v2 全面分析：树形浏览与目录选择（fs-tree-analysis）· 仅分析未实施

> 用户澄清：要的是**文件浏览器**，不只是工作区管理——要支持**树结构选择具体文件夹**。
> 本文档全面重审 v1 原型（639becd）的设计缺口，给出 v2 完整方案。不实施。

---

## 一、v1 原型的定位偏差（诚实复盘）

v1 交付的东西按"工作区管理器"做了：根列表是**平铺卡片**，目录浏览是**平面网格 + 逐层点入**，树只存在于面包屑里。这回答了「工作区在哪」但没回答「**里面长什么样**」：

| 缺口 | 用户要的 | v1 现状 |
|---|---|---|
| **树形浏览** | 展开式目录树（Explorer/VSCode 侧栏形态），看得见层级结构 | 平面网格，一次只见一层，层级感全靠面包屑脑补 |
| **树中选文件夹** | 在树上直接把某个**子文件夹**选为工作区/关联/对话上下文 | 只能在根级别选；子目录要先删根再重新登记整路径，绕远 |
| **盘符内导航** | 点盘符能进去一层层往里走 | 点盘符只弹提示"请登记工作区"（原型砍掉的半成品） |
| **多根全景** | 所有根并列可见，像书签栏一样直接跳 | 有，但与浏览割裂：选根后看不见其他根 |

结论：v1 是「**工作区注册器**」，v2 要补成「**文件浏览器**」——树是主体，工作区只是树上的一种操作。

## 二、v2 信息架构：一棵树，三种动作

```
┌────────────────────────────────────────────────────────┐
│ [C:] [D:]  ←盘符条（点击展开为树根节点，见 §四）        │
│ ┌────────────────────────────────────────────────────┐ │
│ │ ▼ 📁 workspace（内建根）              [✓ 工作区]   │ │
│ │   ├─ 📁 docs/                          [链]        │ │
│ │   ├─ 📁 src/                                       │ │
│ │   ├─ 📄 notes.txt  (点击预览 → 右侧抽屉)           │ │
│ │ ▼ 📁 D:\space\base\polaris-lite（用户根）           │ │
│ │   ├─ ▼ 📁 plugins                                   │ │
│ │   │   ├─ 📁 chat-lite                               │ │
│ │   │   └─ 📁 file-browser                            │ │
│ │   └─ 📄 package.json                                │ │
│ └────────────────────────────────────────────────────┘ │
│              文件夹节点右键/悬浮操作（§三）             │
└────────────────────────────────────────────────────────┘
```

**核心定案：树节点 = 一等公民，文件夹选择不再经过"登记根"**。

树上每个**文件夹节点**直接支持三个动作（悬浮显示，或右键菜单）：

| 动作 | 语义 | 服务端 |
|---|---|---|
| **设为工作区** | 该文件夹成为 activeRoot——bash cwd 跟随；**不需要先登记为根** | 需要服务端支持「临时根」（见 §三） |
| **关联（链）** | 该文件夹加入 linkedRoots（AI 只读上下文） | 同上 |
| **发到对话** | 把该文件夹路径注入输入框（"帮我看看这个目录…"） | 无需服务端（纯前端 onCompose） |

文件节点动作：**预览**（现有）+ **发到对话**（路径/片段注入）。

## 三、服务端配套：从「根白名单」到「会话内临时根」

v1 的安全模型是「只有登记过的 root 才可访问」。树中选任意文件夹要求放宽到「**登录用户的会话内**可访问任意非禁区目录」，否则树只能长在已登记根之下，用户在 D:\space 下没登记根就什么都看不见——这正是"盘符点不进去"的根因。

### 3.1 三级访问模型（替代 v1 单级）

| 级别 | 生命周期 | 能力 |
|---|---|---|
| **L0 会话浏览**（新增） | 会话 cookie 有效期内 | 只读 list/read 任意非禁区目录。**不落盘**——重启即消失，不出现在 roots 列表 |
| **L1 登记根**（v1 已有） | 落盘 workspace-roots.json | 可标记为工作区/关联；跨会话存在 |
| **L2 内建 workspace** | 永久 | bash 的默认 cwd（不变） |

树中「设为工作区」时：若该文件夹不在 L1 根内，**自动把它登记为 L1 根**（一次点击完成"选文件夹=选工作区"的语义闭环），然后标记 active。这样工作区语义仍然永远落在白名单根上，bash 的 cwd 校验不用改。

### 3.2 fs-api 变更清单

1. **`GET /api/fs/tree`**（新增，树的主通道）：
   ```
   入参：path（绝对路径，盘符/根/任意已展开节点；默认 '/'=列出所有盘符+所有 L1 根）
   出参：{ nodes: [{name, isDir, path, isRoot?, rootId?, hasChildren}] }
   ```
   `hasChildren`：目录是否有子项（readdir 只取第一项判断，避免空目录展开箭头）；**只返回一层**，子层点击再拉（懒加载——大目录性能与 v1 网格一致）。
2. **`L0 任意路径 list`**：`/api/fs/list` 放开 `rootId` 限制为可选——无 rootId 时按**绝对路径**浏览，但**禁区校验不变**（dataDir/系统目录/越界全部照旧硬拒）。审计记录 mode: 'session'。
3. **`POST /api/fs/roots/from-path`**：把"树中选中"一步转成登记（内部就是现有 add，只是前端从树节点直接调用）。
4. 限额收紧（L0 漫游比根内浏览更敏感）：目录 500 项不变；**树深度不限但审计翻倍记录**；文本预览降为 256KB（L0）/512KB（L1 根内）。
5. PLITE_FS=0 全局禁用不变；可加 `PLITE_FS_SESSION=0` 只禁 L0 保留根内浏览（公网形态的第二档）。

### 3.3 树形 UI 关键决策

- **懒加载展开**（不是一次性全树）：点击 ▶ 才拉子层——千项目录不卡；`hasChildren=false` 不渲染箭头。
- **目录排序**：文件夹优先 + 字母序（zh locale，与 v1 一致）；隐藏文件依旧过滤。
- **树 vs 根卡片并存**：L1 根作为树的**固定顶部节点**（像 VSCode 工作区文件夹），用户点盘符进入 L0 漫游树；两侧共存一棵树组件，数据同源。
- **选择态**：文件夹 hover 出操作钮（工作区/链/发送）；当前 activeRoot 在树上用 ✓ 徽标标记——与面板底部（或缩略）根状态一致，单一状态源仍是 cap.config 偏好。
- **右键菜单 vs 悬浮钮**：面板窄（300px），悬浮三钮放得下（v1 根卡片已验证此模式）；右键菜单作为增强后置。
- **键盘**：↑↓ 移动、→展开、←收起、Enter 预览/进入——纯加分项，第二梯队。

## 四、「不只是工作区管理」的其余全面性缺口（树之外）

1. **搜索**：树面板顶部加过滤框（当前层 glob 过滤即可，v2.5 再谈递归索引——韦编插件有现成 BM25 可后接）。
2. **文件操作**：v2 明确**继续只读**。删除/重命名/新建不是文件浏览器的职责，是 bash 工具的（有审批链）；避免第二写路径是 v1 就定下的纪律。
3. **预览增强**：文本预览现已在；图片 base64 预览已实现但 mime 写死 png（修：按扩展名给 mime）；大文件 head/tail 片段按钮（服务端参数已支持，UI 未暴露）。
4. **发到对话**（onCompose 通道）：文件→`把这个文件给我讲讲：<rootId 路径>`；文件夹→`帮我分析这个目录的结构：<路径>`。这是"文件浏览器配合 AI 对话"的最直接桥梁，v2 必做。
5. **AI 读树**：cap.tool.fs 增加 `tree` 动作（复用 /api/fs/tree，返回单层+hasChildren）——AI 能自己探索目录结构而不必知道根 id。agent-loop 的 system prompt 同步告知「可用 files 工具浏览」。
6. **排序/刷新**：树顶放"刷新当前节点"钮（外部改动后）；mtime 显示进树 tooltip。
7. **多选**（v3 方向）：checkbox 多选文件→"打包发对话"；本期不做，但树数据结构设计时别挡路。

## 五、实施切分（确认后按序做，每步可独立验收）

| 批 | 内容 | 量 |
|---|---|---|
| T1 服务端 | /api/fs/tree + L0 任意路径浏览（禁区/限额/审计不动摇）+ roots/from-path | ~120 行 |

| T5 打磨 | 搜索过滤/图片 mime/head-tail 钮/刷新 | ~80 行 |

宿主改动：**零**（fs-api 本就是平台设施层）；全部落在 file-browser 插件 + fs-api.mjs。

## 六、风险与决策点（需要用户拍板）

1. **L0 会话漫游的安全面**：公网穿透下，任何登录者可浏览全盘非禁区目录。缓解=PLITE_FS_SESSION=0 开关+审计。**建议公网开着时保持只允许 L1**；本机开发用全功能。→ 需要你确认默认值。
2. **「设为工作区」自动登记根**：语义顺滑但会悄悄往白名单加条目（落盘）。备选：会话级工作区不落盘（重启回 workspace 默认）。**推荐自动登记**（显式用户动作产生持久结果，且 Bash 面板可见可删），但值得你知情。
3. 大目录树深（node_modules 类）：懒加载天然规避；不做跳过规则（.git 之类已在隐藏过滤内，node_modules 保留——AI 依赖分析要用）。
