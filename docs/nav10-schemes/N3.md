# N3 · 命令面板式（Ctrl+K 风格：搜索框 + 模糊匹配列表，回车即切）

> 参考对象：Polaris ToolSwitcher 的**搜索行**与**滚动结果区**视觉（bg-elevated、圆角输入框、行式选项、is-active 高亮、底栏），交互范式换成 **command palette**（Raycast / VS Code Ctrl+K / Linear 风格）。
> 对应总纲表 N3：左侧为「命令面板」——搜索框 + 模糊匹配结果列表，回车即切；面板多时靠搜索而非罗列。

---

## 1. 交互结构图（文字图）

```

│ sidebar        │   stream    │ panel │
│                │             │       │
│ 品牌           │   消息流    │ 面板  │
│ ────────────── │             │       │
│ ┌────────────┐ │             │       │
│ │⌕ 搜索面板  │ │←常驻命令输入 │       │
│ │  ⌘K        │ │             │       │
│ ├────────────┤ │             │       │
│ │ 匹配结果   │ │             │       │
│ │ ▸ 置顶分组 │ │  空query时   │       │
│ │   文件 Git │ │  显示推荐集  │       │
│ ├────────────┤ │             │       │
│ │ ▸ 全部分组 │ │             │       │
│ │   终端     │ │  输入时变    │       │
│ │   浏览器   │ │  模糊匹配    │       │
│ │   模型管理 │ │             │       │
│ │   ↳ 滚动   │ │             │       │
│ ├────────────┤ │             │       │
│ │ 底栏:当前侧栏│ │            │       │
│ └────────────┘ │             │       │
│ 会话列表       │             │       │
└────────────────┴─────────────┴───────┘

键盘事件序（本方案的核心）：
[全局 keydown Ctrl/Cmd+K]
  → focus .palette-input，进入「命令模式」（结果区高亮当前项 cursorIdx）
[输入 query]
  → 模糊匹配（子序列匹配 + 拼音/首字母可选）→ scoredItems 排序渲染
  → cursorIdx 重置为 0（第一项）
[ArrowDown / ArrowUp]
  → cursorIdx ± 1（循环），滚动 active 行 into view
[Enter]
  → items[cursorIdx].onSelect() → 切面板 → 清空 query → blur
[Escape]
  → 清空 query、退出命令模式（结果区回到推荐集）
[鼠标 hover]
  → cursorIdx 同步为 hover 行（键盘/鼠标共用同一高亮）
```

与 N2 的区别：**列表只是搜索结果的展示**，不是「全量罗列」；导航动作以键盘为主、点击为辅；空 query 时展示的是「推荐/置顶子集」而非全部面板。

## 3. 10+ 面板时的表现与数据流

- **数据源**：`slotRegistry.list('panel')` → items；与 N1/N2 共用 `panelNav.ts` 适配。
- **面板多时的核心策略——「搜而不列」**：
  1. 空 query 时结果区只渲染**置顶组（≤4）+ 最近使用组（≤6）**，其余面板不出现，视觉恒定不随面板数膨胀；
  2. 有 query 时做**模糊匹配**：`fuzzyScore(query, label + description + group)`——子序列匹配打分（连续命中加分、词首命中加分），按分排序取前 20 条；
  3. 结果上限 20 条 + 底部「还有 n 个结果，继续输入缩小范围」提示行，避免超长列表；
  4. 全局面板浏览诉求由「输入空格/短词」或后续可加的「`*` 显示全部」满足——本方案明确**不承诺无搜索的全量罗列**。
- **数据流**：
  `registry → items`；`query → fuzzyScore → scoredItems（useMemo）`；`cursorIdx 独立 state，随 query 重置 0`；`Enter → scoredItems[cursorIdx].onSelect() → activePanelId 更新 → panel 槽切换 + 头部/底栏 chip 更新 + query 清空`。
- **焦点管理**：Ctrl+K 全局监听（挂在 navStore 层，注意在 input 聚焦时也响应——命令面板的惯例是即使正在输入也允许 ⌘K 劫持到面板搜索）；Escape 仅在 query 非空或命令模式时消费。
- **移动端**：≤768px 无键盘，Ctrl+K 提示隐藏，退化为「搜索框 + 点击结果」的纯点选模式；kbd 元素 `display:none`。

## 4. 优缺点

**优点**
1. **面板数量几乎不影响界面**：推荐集恒定大小，10 个还是 50 个面板，sidebar 视觉重量不变——这是 10 方案里对「面板多」最免疫的一个。
2. **键盘效率极高**：Ctrl+K → 输入 → 回车三步切任意面板，对高级用户是所有方案里最快的路径；↑↓ 循环 + aria-activedescendant 无障碍性也最好。
3. **视觉延续 ToolSwitcher**：搜索行/滚动区/底栏/is-active 高亮全部沿用，只是把 grid 换成行式结果列表，一致性得分高。
4. **可扩展成全局命令入口**：同一 palette 未来可纳入「新会话/切换模型/打开设置」等命令，不止切面板——架构上留了后路。

**缺点**
1. **无 query 时看不到全量面板**：发现性弱于 N2 的全量罗列；新用户可能不知道有哪些面板，需要靠「最近使用/置顶」补偿，冷启动时推荐集可能不准。
2. **模糊匹配要写对**：中文面板名的拼音/首字母匹配、连续命中加分等细节做不好会出现「搜不到明明存在的面板」，是本方案的主要实现风险。
3. **键盘焦点抢占需谨慎**：全局 Ctrl+K 会劫持输入焦点，若用户正在会话输入框打字，处理不当会打断输入（需像 ToolSwitcher 的 hover 不抢焦点语义一样明确规则）。
4. **移动端体验降级明显**：无键盘时方案优势（键盘流）完全消失，只剩一个普通搜索框，等于退化为 N10 的子集。

## 5. 与 ToolSwitcher 的异同对照表

| 维度 | Polaris ToolSwitcher | N3 方案 |
|---|---|---|
| 形态 | 浮层（click/hover 打开） | sidebar 常驻命令面板（无开关状态） |
| 主交互 | 视觉扫视 grid + 点击 | 键盘输入 + 模糊匹配 + 回车 |
| 搜索行 | 有，过滤上方 grid | 有，且是唯一入口（核心） |
| 匹配算法 | 简单 includes | 模糊子序列打分 + 排序 + 上限 20 |
| 置顶区 | 4 列 icon grid | 「置顶」分组行式列表（空 query 时展示） |
| 溢出区 | 3 列 grid 全量罗列 | 无全量罗列；有 query 才出匹配结果 |
| 键盘导航 | 无（仅 Escape） | Ctrl+K / ↑↓ / Enter / Escape 完整链路 |
| 底栏 | 当前侧栏 + 关闭按钮 | 当前侧栏 + 快捷键说明（无关闭钮） |
| 视觉 token | bg-elevated / 圆角输入框 / is-active | 完全沿用 |
| 空态 | 「没有匹配结果」 | 同左 + 「继续输入缩小范围」提示 |
| 数据源 | toolSwitcherData + 面板 | slotRegistry panel 槽（共用适配层） |

## 6. 实施步骤清单

1. **数据适配**：复用 `panelNav.ts`；为每项补充 `keywords`（label 拆词 + 可选拼音首字母），供模糊匹配。
2. **模糊匹配器**：新建 `src/core/fuzzyMatch.ts`——`fuzzyScore(query, text): number | null`，实现子序列匹配 + 连续/词首加分；配 6+ 个 vitest 用例（中文、英文、大小写、无命中）。
3. **组件实现**：新建 `src/core/PanelPalette.tsx`——常驻搜索框 + 结果区 + 底栏；state：`query / cursorIdx / commandMode`；`scoredItems = useMemo(fuzzy)`；空 query 渲染「置顶 + 最近使用」两组。
4. **键盘链路**：组件内 `onKeyDown` 处理 ArrowUp/Down（循环 + `scrollIntoView({block:'nearest'})`）、Enter（select + 清空）、Escape（清空 query）；navStore 层挂全局 `Ctrl/Cmd+K` 监听 focus 输入框；确认会话输入框打字时的劫持规则并写注释。
5. **激活接线**：同 N2——`onSelect → activePanelId → panel 槽 Tab 同步`；底栏与 aria-activedescendant 实时联动 cursorIdx。
6. **样式**：`styles.css` 增加 `.panel-palette/.palette-*/` 类，行式列表样式；`kbd`、分组标题、结果上限提示行；≤768px 隐藏 kbd。
7. **验证**：12 个模拟面板下测试——空 query 只显示推荐集；输「git」回车切到 Git 面板；↑↓ 循环高亮；Ctrl+K 在会话输入聚焦时也能唤起；Escape 清空；`tsc` + vitest（fuzzyMatch）通过。
