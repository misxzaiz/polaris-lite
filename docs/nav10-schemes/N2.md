# N2 · 常驻高密度列表（左侧常驻「搜索 + 置顶 grid + 全量列表」，直接点选）

> 参考对象：Polaris `src/components/Layout/ToolSwitcher.tsx` 的内部结构（搜索行 / 置顶 4 列 grid / 溢出 3 列列表 / 底栏），但**不再做成浮层**，而是把这一整套作为 sidebar 顶部的**常驻区块**。
> 对应总纲表 N2：左侧常驻「搜索 + 置顶 grid + 全量列表」，信息密度对齐 ToolSwitcher，直接点选。

---

## 1. 交互结构图（文字图）

```
┌────────────────┬─────────────┬───────┐
│ sidebar        │   stream    │ panel │
│                │             │       │
│ 品牌           │   消息流    │ 面板  │
│ ────────────── │             │       │
│ ┌────────────┐ │             │       │
│ │ 搜索行     │ │←常驻，不消失 │       │
│ ├────────────┤ │             │       │
│ │ 置顶 grid  │ │  4 列大按钮 │       │
│ │ ▦   ⑂   📁 │ │             │       │
│ ├────────────┤ │             │       │
│ │ 全量列表   │ │  3 列紧凑   │       │
│ │ ▸ 终端     │ │             │       │
│ │ ▸ 浏览器   │ │  随输入过滤 │       │
│ │ ▸ 模型管理 │ │             │       │
│ │ …(滚动)    │ │             │       │
│ ├────────────┤ │             │       │
│ │ 底栏:当前侧栏│ │            │       │
│ └────────────┘ │             │       │
│ ────────────── │             │       │
│ 会话列表       │             │       │
│ (被压缩但保留) │             │       │
└────────────────┴─────────────┴───────┘

事件顺序（无弹层，全部同步发生）：
[用户输入 .switcher-search-input]
  → query 变化 → filteredItems 重算 → 置顶区/列表区即时重渲染（无动画延迟）
[用户点击 .tool-item]
  → onSelect(panelId) → activePanel 更新
  → 当前面板项加 .is-active；panel 槽 Tab 切换
  → 不关闭任何东西（列表常驻）
[面板注册/注销]
  → slotRegistry 变化 → items 重算 → 列表增量更新
```

与 N1 的本质区别：**没有开/合状态机**。`isOpen` 恒为 true，搜索框永远在，用户视线不用移动就能看到全部面板。

## 2. HTML 骨架层级（class 命名对齐 ToolSwitcher 风格）

常驻区块插在 sidebar 槽内、会话列表上方，复用 ToolSwitcher 的 class 体系但去掉浮层定位：

```html

    <!-- 头部：单行 -->
    <div class="switcher-header">
      <span class="switcher-header-icon">▦</span>
      <span class="switcher-header-title">面板</span>
      <span class="switcher-active-chip">文件</span>   <!-- 当前面板，实时联动 -->
    </div>                                            <!-- 常驻无关闭按钮 -->

    <!-- 搜索行 -->
    <div class="switcher-search-row">
      <div class="switcher-search-box">
        <span class="switcher-search-icon">⌕</span>
        <input class="switcher-search-input" placeholder="搜索面板"
               aria-controls="panel-dock-list" />
      </div>
    </div>

    <!-- 滚动区（常驻，flex-1 min-h-0） -->
    <div class="switcher-scroll" id="panel-dock-list">

        <button class="tool-item tool-item-pinned is-active" role="option" aria-selected="true">
          <span class="tool-item-icon">📁</span>
          <span class="tool-item-label">文件</span>

      </div>

          <span class="tool-item-icon">>_</span>
          <span class="tool-item-label">终端</span>

      </div>
```

## 3. 10+ 面板时的表现与数据流

- **数据源**：与 N1 相同，`slotRegistry.list('panel')` → `PanelNavItem[]`；区别是**无 query 时不折叠任何项**——10 个面板就是 4 个置顶 + 6+ 个溢出全部平铺。
- **空间策略（核心权衡）**：
  1. dock 区 `max-height: 52%` 封顶，内部滚动；会话列表占剩余空间，二者以 `flex` 分割，任何一方内容多都只在自己的滚动区内滚；
  2. 面板到 15+ 时溢出 grid 行数增加，用户滚动 dock 区浏览；搜索仍是第一优先直达手段；
  3. 可选增强（原型可不做）：溢出区超过 12 项时默认折叠显示前 9 个 + 「展开全部 (n)」行，展开状态存 navStore。
- **数据流**：`registry 变化 → items；query 输入 → filteredItems（label/description/group includes）；点击 → onSelect → activePanelId → is-active 类切换 + panel 槽 Tab 同步 + 底栏/头部 chip 文案更新`。全程同步 setState，无定时器、无浮层生命周期。
- **会话列表保护**：`SlotOutlet slot="sidebar"` 产生的会话列表外层加 `min-height: 120px`，防止面板极多 + dock 满高时把会话列表压没。
- **移动端**：≤768px 时 dock 不常驻，改为 sidebar 抽屉打开后出现在会话列表上方（结构不变，仅容器样式切换）。

## 4. 优缺点

**优点**
1. **零层级、直达性最强**：所有面板永远可见，点一下就切，没有浮层开合成本；对高频切换用户效率最高。
2. **实现最简单、状态最少**：没有 isOpen/openMode/锚定/外点关闭一整套弹层状态机，纯受控组件，bug 面最小。
3. **视觉与 ToolSwitcher 完全一致**：直接复用其 class 体系与分区逻辑，评审的「视觉一致性」维度天然满分。
4. **可发现性好**：新面板注册后立刻出现在列表里，不需要用户知道入口在哪。

**缺点**
1. **常驻空间成本**：sidebar 顶部被 dock 永久占用（搜索行 + 置顶 grid 至少 ~150px），会话列表可见条目减少；这是本方案最大的体验代价。
2. **面板很多时信息过载**：20+ 面板全量平铺，扫视负担上升，需要搜索/折叠等辅助机制补位（本方案已含搜索，折叠为可选）。
3. **与 Polaris 语义有偏移**：ToolSwitcher 本是「低频入口 + 按需展开」的设计，常驻化后失去了「平时干净」的特性，算是对参考实现的改写而非复用。
4. **移动端要另做一套**：常驻结构在小屏抽屉里太占空间，必须为 ≤768px 设计降级形态，增加实现面。

## 5. 与 ToolSwitcher 的异同对照表

| 维度 | Polaris ToolSwitcher | N2 方案 |
|---|---|---|
| 形态 | fixed 浮层，按需出现 | 常驻 dock，永远可见 |
| isOpen 状态 | 有（click/hover 双模式） | 无（恒 true，删掉整个开关状态机） |
| 触发/关闭 | 按钮 + mousedown 外部 + Escape | 不存在；搜索框常驻可直接输入 |
| 头部 | 标题 + chip + 关闭钮 | 标题 + chip（无关闭钮） |
| 搜索行 | 相同结构；click 打开才 focus | 相同结构；常驻可随时 focus |
| 置顶 4 列 grid | 有 | 有（原样保留） |
| 溢出 3 列 grid | 有，浮层内滚动 | 有，dock 内滚动（max-height 52%） |
| 底栏「当前侧栏」 | 有，随浮层出现 | 有，常驻可见 |
| 数据源 | toolSwitcherData 静态+面板 | slotRegistry panel 槽动态 |
| 空间归属 | 覆盖在内容之上，零常驻成本 | 占用 sidebar 顶部空间 |
| 选中后行为 | onSelect + onClose | onSelect（不关闭） |

## 6. 实施步骤清单

1. **数据层复用**：直接复用 N1 的 `src/core/panelNav.ts`（`usePanelNavItems()`），两方案共用同一数据适配。
2. **组件实现**：新建 `src/core/PanelDock.tsx`——复制 ToolSwitcher 的头部/搜索行/置顶 grid/溢出 grid/底栏 JSX 结构，删除浮层定位 effect、isOpen 判断、mousedown/Escape 监听、关闭按钮。
3. **激活状态接线**：`activePanelId` 由 navStore 持有；点击 `onSelect` 更新它，并同步 `SlotOutlet` panel 槽的 `activeIdx`（将 activeIdx 提升为可从外部设置，或经事件总线 `emit('panel-activate', pluginId)`）。
4. **空间约束**：`styles.css` 中给 `.panel-switcher-dock` 设 `max-height: 52%` + 内部滚动，给会话列表容器设 `min-height: 120px`，验证两者同时内容溢出时各自独立滚动。
5. **空态与过滤**：实现 `switcher-empty`；确认 query 命中置顶项时溢出区为空不渲染分隔线（对齐 ToolSwitcher 条件渲染逻辑）。
6. **移动端降级**：≤768px 时 dock 移入 sidebar 抽屉顶部（或提供折叠按钮），复用现有 drawer 状态。
7. **验证**：注册 12 个模拟面板，检查 4+3 列渲染、搜索过滤、is-active 联动、底栏文案、会话列表不被压没；`tsc` 通过。
