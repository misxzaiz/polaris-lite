# N9 · 时间线 / 最近使用（Recency Timeline）

> 代号 N9。核心交互：左侧栏是一个按「最近使用时间」倒序排列的面板流（类似历史记录 / 浏览器历史），刚用过的面板自动排到最前；支持搜索过滤与「置顶固定」（置顶项不随时间下沉）。无需用户做收藏决策，行为本身形成个性化排序。

---

## 1. 交互结构图（文字图）

```
┌─ 左侧栏（240px，面板段）─────────────┐
│  ⏱ 面板 · 最近使用                   │
│  ─────────────────────────────       │
│  🔍 搜索面板…          [置顶 2]      │
│  ─────────────────────────────       │
│  📌 置顶（固定，不下沉）             │
│   ├ [icon] 文件          2 分钟前     │
│   └ [icon] 终端          1 小时前     │
│  ─────────────────────────────       │
│  最近使用（倒序时间线）              │
│   ├ ● [icon] 变更        刚刚    ←    │
│   ├ ○ [icon] 浏览器      5 分钟前     │
│   ├ ○ [icon] AI 控制台   昨天         │
│   ├ ○ [icon] 集成        3 天前       │
│   ├ ○ [icon] 开发者      上周         │
│   └ ○ [icon] 日历        更早         │
│  ─────────────────────────────       │
│  （时间线滚动；下方接会话列表）       │
└──────────────────────────────────────┘

时间线节点交互：
  ● 当前激活面板（primary 色实心点）
  ○ 历史面板（border-subtle 空心点）
  hover 行 → 出现 📌（置顶/取消置顶）与相对时间
```

事件顺序：
1. 每次激活某面板（`onSelect` / 外部路由激活），写 `lastUsedAt[panelId] = Date.now()` 并持久化；
2. 列表渲染顺序 = 置顶组（保持固定或按最近使用）→ 非置顶按 `lastUsedAt` 倒序；从未用过的面板按「注册顺序」垫底，标「未使用」；
3. 搜索输入 `query` → 过滤 `label/description/group`（与 ToolSwitcher 同规则）；搜索时隐藏时间分组标题，呈平铺结果；
4. 置顶数量上限建议 4，超出时提示「置顶已满，请先取消一个」。

## 3. 10+ 面板时的表现与数据流

- **自动个性化**：面板总数增长不影响顶部体验——用户最近实际用过的 3~5 个永远在最前，长尾自然沉底，无需任何整理动作。
- **数据流（单向）**：
  1. `panels: ToolSwitcherItem[]`（静态注册）+ `usage: Record<panelId, { lastUsedAt: number; pinned?: boolean }>`（持久化，key `polaris.panelUsage`）；
  2. `onSelect(panelId)` 触发 `touch(panelId)` → 更新 `usage` → 触发重排；重排用 `useMemo` 依赖 `[panels, usage, query]`；
  3. 渲染顺序：`pinned`（组内按 lastUsedAt 倒序）→ 其余按 lastUsedAt 倒序 → 从未使用按注册序；
  4. 搜索时 `filtered = panels.filter(match(query))`，再套用同一排序函数（保持「搜出来的也是最近优先」）；
  5. 时间戳非高频刷新：相对时间组件以 60s 间隔重算（`setInterval` + 清理），避免每秒全列表重渲。
- **10+ 压力点**：50 个面板时时间线就是 50 行列表，靠搜索 + 置顶两组缓解；建议滚动区在「最近使用」超过 20 行时显示「显示更早的面板」折叠按钮（懒展开），防止一次渲染过长。
- **防抖动**：面板切换频繁时避免列表跳动——对 5 秒内的重复激活不重排（或对排序位置做 CSS `transition: transform` 平滑移动）。

## 4. 优缺点

**优点**
1. 零配置个性化：不需要用户预先收藏/整理，高频面板自然浮顶，冷启动即可用；
2. 时间上下文有额外信息价值（「我刚用过哪个」），对多面板工作流（文件→终端→变更 循环）特别顺手；
3. 视觉上天然承载 ToolSwitcher 的 grid/底栏语言，且时间线形态与「会话历史列表」心智一致，学习成本低。

**缺点**
1. 排序动态变化可能造成「肌肉记忆失效」：用户记住了某面板在第 4 行，下次来变成第 2 行；需要置顶机制兜底；
2. 需要维护 usage 持久化与相对时间刷新，状态管理比静态列表复杂；
3. 长尾面板沉底后，低频面板的可达性反而下降（比字母序/分组更难被发现）；
4. 「刚刚/5 分钟前」等相对时间在跨天、跨时区场景有边界情况需处理。

## 5. 与 ToolSwitcher 的异同对照表

| 维度 | ToolSwitcher（参考实现） | N9 时间线/最近使用 |
|---|---|---|
| 存在形态 | 浮层（临时打开） | 常驻侧栏面板段 |
| 排序依据 | 固定：置顶集 + 注册序 | 动态：lastUsedAt 倒序 + 置顶固定 |
| 搜索 | 浮层搜索行 | 常驻搜索行，同过滤规则 |
| 置顶 grid | `PINNED_LEFT_PANEL_TYPES` 4 列 grid | 用户可置顶（≤4），纵向时间线行而非 grid |
| 溢出列表 | 3 列紧凑 grid | 时间线行（icon+label+相对时间） |
| 底栏 | 当前侧栏 + 关闭 | 保留同构底栏 |
| 状态管理 | 无持久状态（items 由外部传入） | 新增 usage 持久化 + 时间刷新 |
| 打开/关闭语义 | 有（浮层生命周期） | 无（常驻，无开关） |

## 6. 实施步骤清单

1. 定义 `panelUsage` 存储模块：`load/save`（localStorage 或 kv）、`touch(panelId)`、`togglePin(panelId)`、PIN 上限 4；
2. 实现 `useRelativeTime(ts)` hook：返回「刚刚/N 分钟前/…」，组件级 60s 定时刷新，卸载清理；
3. 实现 `PanelTimeline` 组件骨架（header/search/scroll/footer 四段），class 按上文命名；
4. 实现排序 memo：`sortPanels(panels, usage, query)`，先 pinned 后 recency，未使用垫底；
5. 渲染置顶组与最近使用组，行内含 dot、icon、label、time、pin 按钮（hover 显现）；
6. 接入面板激活事件：在现有 `onSelect` 与外部激活路径统一调用 `touch()`（注意幂等：同面板重复激活不产生多余记录）;
7. 搜索过滤接入（规则与 ToolSwitcher 一致：`label description group` 小写 includes）；
8. 长列表优化：>20 行时「显示更早的面板」折叠；排序变化加 150ms transform 过渡；
9. 自测清单：首次进入（无 usage）按注册序、激活后即时上浮、置顶不随使用下沉、取消置顶恢复动态排序、搜索时两组合并平铺、Escape/焦点行为、跨天时间显示。
