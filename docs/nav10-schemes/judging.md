# 面板导航 10 方案评审 · 评委 A

> **评委视角**：信息架构与可扩展性（多面板查找效率、分组逻辑、长期扩展成本优先）。
> **评分维度与权重**：A 信息架构合理性 40% / B 交互体验 30% / C 实现可行性 20% / D 视觉与一致 10%。单项 1–10、0.5 步进；总分 = Σ(维度分 × 权重)。
> 评审对象：`docs/nav10-schemes/N1.md` ~ `N10.md`；视觉参照 `Polaris/src/components/Layout/ToolSwitcher.tsx`。

## 一、逐方案评分

### N1 · ToolSwitcher 浮层（单入口 + 点击弹出）
**A 8.5 / B 8.0 / C 9.0 / D 10.0 → 总分 8.60**
单入口 + 按需展开是成熟的渐进式披露范式：常态零占用，会话列表完全不被挤压；面板增多只增加浮层滚动长度，置顶 grid + 溢出列表 + 搜索三层结构与 ToolSwitcher 完全同构，扩展性最好。扣分点在发现性——面板列表默认不可见，新用户需要一次「点开才知道」；浮层打开时遮挡消息流。

### N2 · 常驻高密度列表
**A 7.5 / B 8.0 / C 9.0 / D 10.0 → 总分 8.20**
零层级直达、全量可见，查找效率在小规模（≤12）下最高；实现最简单、状态最少。但 IA 上只有「置顶 / 溢出」两层、无真正分组，20+ 面板全量平铺后扫视负担陡增，只能靠滚动消化；常驻 dock 永久占用 sidebar 顶部约 150px，会话列表是结构性受害者。

### N3 · 命令面板式（Ctrl+K）
**A 8.5 / B 7.5 / C 7.0 / D 9.0 → 总分 7.95**
「搜而不列」对面板数量最免疫：推荐集恒定，50 个面板也不膨胀；键盘链路（Ctrl+K → 输入 → 回车）是全方案最快的切换路径，且未来可扩成全局命令入口。但浏览型查找（不知道面板名）弱，冷启动推荐集可能不准；移动端无键盘后优势归零；中文模糊匹配的质量是实现风险。

### N4 · 顶部横滚条
**A 7.0 / B 7.0 / C 6.5 / D 8.0 → 总分 7.00**
横向消化面板数量、不占纵向空间，sidebar 彻底解放，架构解耦干净。但导航脱离侧栏后与右侧 panel 槽的对应关系变弱；溢出 chip 藏在滚动后，发现性要靠渐隐 mask + 「+n」+ 浮层兜底三件套补偿；chip 条 + 兜底浮层两套交互的状态同步面大，实现成本被低估。

### N5 · 图标 rail + 抽屉
**A 7.0 / B 6.5 / C 6.0 / D 7.5 → 总分 6.70**
rail 宽度恒定、滚动消化任意数量，结构性不挤压；「浏览（抽屉详情）与激活分离」有信息增量。但 IA 上 rail 是无分组的纯图标序列，10+ 面板时图标辨识度成为查找瓶颈；从看图标到进面板要两跳；shell 由三栏变四栏、`railOpenPanelId` 与 `activePanelId` 双状态失步风险，改动面在 10 方案里偏大。

### N6 · 树形折叠
**A 9.0 / B 7.0 / C 6.0 / D 8.5 → 总分 7.75**
纯 IA 视角的最强方案：分组 → 子分组 → 面板的真树 + 折叠，使「可见条目数」与「面板总数」彻底解耦，几十个面板也从容；搜索自动展开命中路径兼顾浏览型与目标型查找；拖拽排序 + 持久化让用户建立自己的心智模型；分组语义可直接复用 ToolSwitcher 的 `ToolGroupId`。代价是实现复杂度全方案最高（递归树 + 折叠动画 + DnD + 注册表 merge），深层叶子的点击路径也偏长。

### N7 · 分屏 Tab 条
**A 6.5 / B 6.5 / C 7.0 / D 8.5 → 总分 6.80**
Tab 直达 + 预览区的「先看再切」思路有价值，但 260px 侧栏只放得下 3–4 个 chip，绝大多数面板被收进 ⋮ 下拉——「直达」名存实亡，IA 上等于把可达性押注在一个收纳抽屉里；横滚发现性差；预览区固定占约 162px，进一步压缩会话列表；双档位（直切/预览）徒增状态与理解成本。

### N8 · 收藏优先
**A 7.0 / B 7.5 / C 8.5 / D 9.0 → 总分 7.65**
收藏区恒定 6 格，认知负担 O(1)，日常路径最短，左栏高度可预测。但「收藏」是把分组成本转嫁给用户：冷启动依赖默认收藏是否贴合工作流；非收藏面板两跳可达；「我的收藏」与浮层内「系统置顶」两套常用概念语义重叠，需要文案上小心区分。实现上几乎完全复用 ToolSwitcher 浮层，成本低是明显优点。

### N9 · 时间线 / 最近使用
**A 6.5 / B 7.5 / C 7.0 / D 7.5 → 总分 7.00**
零配置个性化是亮点：高频面板自然浮顶，不需要用户做整理决策。但「时间」是弱分组维度——无分组、无分类，长尾面板沉底后可达性反而低于字母序/分组方案；动态排序损害肌肉记忆，需置顶兜底；usage 持久化 + 相对时间刷新 + 防跳动处理让状态管理比静态列表复杂一档。

### N10 · 混合：搜索 + 分类 chips + 紧凑列表
**A 8.5 / B 7.5 / C 8.0 / D 8.5 → 总分 8.10**
信息找回能力最强的常驻方案：文本搜索（目标型）+ chips 多选过滤（缩域）+ 分组列表（浏览型）三路叠加；分类轴直接复用 ToolSwitcher 的 `ToolGroupId`，数据零改造；常驻列表让「还有哪些面板」始终可见，发现性优于一切隐藏长尾的方案（N7/N8/N9）。代价是搜索行 + chips + 列表三层结构占垂直空间，会话列表被挤压；chips 与「全部」的互斥状态机细节多。

## 三、前 3 名与冠军推荐

### 前 3 名

1. **N1 ToolSwitcher 浮层（8.60）**——IA 与工程质量的平衡点：常态零占用根治「面板挤压会话列表」，浮层内「搜索 + 置顶 grid + 溢出列表」的分区是被 Polaris 验证过的成熟信息架构，新增面板零成本吸收；实现上可直接移植 ToolSwitcher 的锚定、过滤、关闭语义，风险最低、视觉一致满分。
2. **N2 常驻高密度列表（8.20）**——最简单直接：所有面板永远可见、一点即切，实现与状态管理最轻。适合面板规模可控（≤12）且愿意用会话列表空间换直达性的形态；但面板继续增长后全量平铺的扫视成本会快速恶化。
3. **N10 混合：搜索 + 分类 chips（8.10）**——常驻方案里信息找回能力最强，三路检索叠加且分类轴复用 `ToolGroupId` 零改造；缺点是三层结构对侧栏纵向空间的占用，以及 chips 交互状态机的细节成本。

### 冠军推荐：N1 · ToolSwitcher 浮层

**推荐理由（评委 A 视角）**：

1. **对「面板多」的扩展性最优**：10+ 乃至 30+ 面板都只体现为浮层滚动区的长度，常态界面完全不随面板数变化；N2/N10 的常驻结构会随面板数线性膨胀并持续挤压会话列表，N1 把这种压力隔离在一个按需出现的浮层里。
2. **信息架构成熟且经过验证**：搜索行 / 置顶 4 列 grid / 溢出 3 列 grid / 底栏「当前侧栏」的四段式结构直接继承 Polaris ToolSwitcher，用户从 Polaris 迁移零学习成本；分组语义（`ToolGroupId`、`PINNED_LEFT_PANEL_TYPES`）可原样映射到 polaris-lite 的 panel 槽数据。
3. **实现可行性与视觉一致性双满分区**：锚定定位、query 过滤、mousedown/Escape 关闭、click 才 focus 搜索框等关键行为都有现成参照，改动面集中在 sidebar 内新增一个入口组件；视觉上与参考实现完全同构，D 维度无折损。
4. **保留了向其他方案演进的余地**：入口按钮可扩展 hover 直达（对齐 ActivityBar 的 120ms/300ms 语义）；面板规模进一步膨胀时，浮层内可平滑叠加 N3 的模糊匹配或 N10 的分类 chips，不需要推翻布局骨架。

**落地提醒**：N1 的主要短板是发现性与浮层遮挡。建议入口按钮采用「图标 + 当前面板名 + ▾」的明确文案，浮层打开时对 sidebar 侧做让位处理，并在首次使用时给一次性引导提示，即可补齐短板。

# 面板导航 10 方案评审 · 评委 B

> **评委视角**：工程落地与交互体验（改动面与风险、状态管理复杂度、高频/低频使用动线、移动端降级优先）。

> **代码核对基础**：`polaris-lite/src/core/SlotLayout.tsx`（四槽 grid + `setDrawer` 抽屉状态机）、`SlotOutlet.tsx`（panel 槽 `activeIdx` 为组件内部 `useState`，**任何方案都须先把它受控化/上提**，这是所有方案的公共前置成本）、`types.ts`（`SlotDescriptor` 目前**无 `group`/`icon` 字段**，N6/N10 需契约扩展）、`vite.config.ts`（纯 Vite 前端 + 内嵌 host 中间件，无 Tauri 原生依赖，各方案技术栈风险均等）；`Polaris/src/components/Layout/ToolSwitcher.tsx`（锚定 effect、`openMode` click 才 focus 搜索、`PINNED_LEFT_PANEL_TYPES`、`getToolGroup` 均可直接移植）。

## 一、逐方案评分

### N1 · ToolSwitcher 浮层（单入口 + 点击弹出）
**A 8.5 / B 7.5 / C 9.0 / D 9.5 → 总分 8.40**
工程上是 10 方案里改动面最小、确定性最高的：在 `.shell-sidebar` 内、`SlotOutlet slot="sidebar"` 之前插一个组件即可，锚定 effect、`includes` 过滤、mousedown/Escape 关闭、click 才 focus 四个关键行为都有现成实现可抄，不触碰 SlotLayout 的 grid 与抽屉状态机。交互上「常态零占用」对聊天产品（会话列表是主界面）是最优取舍——面板切换属低频动作，多一次点开浮层的成本可接受；缺点是高频切换用户每次都要重走「点开 → 搜 → 点」动线，且浮层遮挡消息流。

### N2 · 常驻高密度列表
**A 7.0 / B 8.5 / C 9.0 / D 9.0 → 总分 8.05**
交互体验维度的高分方案：零层级、零延迟、一点即切，无任何开合状态机，bug 面最小，实现约半天。但工程上「常驻」是把成本从交互转嫁给布局：`max-height: 52%` 与会话列表的 flex 分割需要反复调校，会话列表可见条目永久减少——对以会话为主界面的产品，这是每天都被感知的代价。面板 ≤12 时体验最佳，继续增长后全量平铺的滚动扫视明显劣化。

### N3 · 命令面板式（Ctrl+K）
**A 8.0 / B 7.5 / C 6.5 / D 8.5 → 总分 7.60**
键盘链路（Ctrl+K → 输入 → 回车）是全方案最快的切换路径，对高级用户体验极佳。但工程风险集中：中文模糊匹配（拼音/首字母）做不好就「搜不到明明存在的面板」；全局 Ctrl+K 劫持焦点与聊天输入框的冲突规则必须精确定义（对齐 ToolSwitcher「hover 不抢焦点」的谨慎语义）；↑↓ 循环 + `aria-activedescendant` + 滚动跟随的键盘链路测试面大。移动端无键盘后优势归零，等于退化为普通搜索。

### N4 · 顶部横滚条
**A 6.5 / B 6.5 / C 6.5 / D 7.5 → 总分 6.60**
sidebar 彻底解放、会话列表零挤压是真实收益，chip 横滚对移动端也天然友好。但交互动线变差：面板在顶部、会话在左侧、内容在右侧，切换时视线横跳；溢出 chip 藏在滚动后，发现性要靠渐隐 mask + 「+n」badge + 浮层兜底三重补偿——这本身就说明主路径不可靠。工程上 chip 直选与浮层兜底两套交互并存，激活态同步面比纯方案大；wheel 转 scrollLeft、scrollIntoView、mask 等细节都是易碎点。

### N5 · 图标 rail + 抽屉
**A 6.5 / B 6.0 / C 5.5 / D 7.0 → 总分 6.20**
工程落地面最大的方案之一：shell 从三栏变四栏（rail 48px 独立成列），SlotLayout 的 grid、移动端抽屉、遮罩逻辑都要适配；`railOpenPanelId` 与 `activePanelId` 双状态天然有失步风险；抽屉「激活后保持展开」与「点击消息区让位收起」的让位策略还要额外设计。交互上「看图标 → 开抽屉 → 点打开」两跳才进面板，10+ 面板时纯图标辨识度低，高频用户会嫌繁琐。

### N6 · 树形折叠
**A 9.0 / B 7.0 / C 5.5 / D 8.0 → 总分 7.60**
信息架构最强（分组 → 子组 → 面板真树 + 折叠 + 搜索自动展开命中路径 + 拖拽排序），几十个面板也从容，且分组语义可复用 ToolSwitcher 的 `ToolGroupId`。但从工程落地看是全方案最贵：递归树渲染、`grid-template-rows` 折叠动画、HTML5 DnD、用户排序与 `slots.list` 变更的 merge（新插件落位、脏 order 清理），四件事叠加；`types.ts` 需为 `SlotDescriptor` 增加 `group` 字段；移动端 DnD 还要再做一套长按 + 箭头降级。深层叶子点击路径长也拉低交互分。

### N7 · 分屏 Tab 条
**A 6.0 / B 6.0 / C 6.5 / D 8.0 → 总分 6.30**
交互核心缺陷：260px 侧栏横滚只放得下 3–4 个 chip，绝大多数面板被收进 ⋮ 下拉，「Tab 直达」名存实亡；双档位（直切/预览）会让用户遇到「点了 Tab 右侧没反应」的困惑，需要很强的默认值与文案才能兜住。工程上 `ResizeObserver` 逐 chip 测宽 + ±1 滞回防抖、⋮ 收纳、预览区摘要、A/B 档位开关，状态面不小而收益有限。

### N8 · 收藏优先
**A 7.0 / B 8.0 / C 8.5 / D 9.0 → 总分 7.80**
工程上性价比很高的方案：浮层部分与 ToolSwitcher 完全同构（搜索/置顶 grid/溢出 grid/底栏照搬），新增的只有 favorites 状态 + localStorage 持久化 + 空位占位，改动面与 N1 同级。交互上「常用面板零搜索零滚动一次直达」体验很好，收藏区恒定 6 格让左栏高度可预测。扣分在冷启动依赖默认收藏是否贴合用户工作流、非收藏面板两跳可达，以及「我的收藏」与浮层「系统置顶」两套常用概念需要文案区分。

### N9 · 时间线 / 最近使用
**A 6.5 / B 7.5 / C 7.0 / D 7.5 → 总分 7.00**
「零配置个性化」的交互理念好：高频面板自然浮顶，不需用户做整理决策。但工程上要维护 usage 持久化、相对时间 hook（60s 定时刷新 + 卸载清理）、排序防跳动（5 秒内不重排 / transform 过渡），状态复杂度比静态列表高一档；激活事件的统一埋点要覆盖 `onSelect` 与外部激活两条路径。交互上动态排序损害肌肉记忆、长尾沉底后低频面板更难被发现，置顶机制只能部分兜底。

### N10 · 混合：搜索 + 分类 chips + 紧凑列表
**A 8.5 / B 7.5 / C 8.0 / D 8.5 → 总分 8.10**
常驻方案里工程与体验平衡得最好：`filterAndGroup(panels, query, selectedCats)` 是纯函数、易测；分类轴直接复用 `ToolGroupId`，插件注册零改造；50 面板一次 filter + 分组即可，无需虚拟化。交互上三路检索（文本 + chips 缩域 + 分组浏览）叠加，发现性是常驻方案中最好的——「还有哪些面板」始终可见。扣分：搜索行 + chips + 列表三层结构常驻占垂直空间，会话列表被压缩；chips 与「全部」的互斥状态机细节多（选中/取消/清空回退），边界要仔细测。

## 三、前 3 名与冠军推荐

### 前 3 名

1. **N1 ToolSwitcher 浮层（8.40）**——工程落地确定性最高：不触碰 SlotLayout 的 grid 与抽屉状态机，只在 sidebar 内插一个自包含组件；锚定、过滤、关闭、focus 语义全部有 ToolSwitcher 现成实现可移植；常态零占用，面板数量增长被完全隔离在浮层内。
2. **N10 混合：搜索 + 分类 chips（8.10）**——常驻方案中综合最优：过滤逻辑是纯函数、分类轴零改造，交互上发现性最强；代价是三层结构常驻占空间与 chips 状态机细节。
3. **N2 常驻高密度列表（8.05）**——交互体验最直接（一点即切、无状态机），实现最快；但会话列表永久被挤压，面板规模增长后体验会明显恶化，适合作为「面板数量可控」前提下的快速落地选项。

### 冠军推荐：N1 · ToolSwitcher 浮层

**推荐理由（评委 B · 工程落地与交互体验视角）**：

1. **改动面最小、风险最低**：从代码现状看，`SlotLayout.tsx` 的四槽 grid、`setDrawer` 抽屉状态机、auth 门禁三段式都不需要动；`SlotOutlet` 的 panel 槽只需把内部 `activeIdx` 受控化（这本来就是所有方案的公共前置）。N1 在此之上只新增「一个入口按钮 + 一个浮层组件」，而 N5 要改四栏 grid、N6 要上递归树 + DnD + merge、N7 要 ResizeObserver + 双档位——N1 的回归面最小。
2. **关键行为全部有验证过的参照**：锚定 clamp 公式、`includes` 过滤、mousedown/Escape 关闭、click 才 focus 搜索框（避免吞正在输入的字符）这些容易出 bug 的细节，`ToolSwitcher.tsx` 里都有现成的正确实现可直接移植，工程不确定性接近零。
3. **交互取舍匹配产品主场景**：这是聊天产品，会话列表是每天盯着的主体，面板切换是低频伴随动作。N1「常态零占用」保住了会话列表完整空间，切换时「点开 → 搜索/扫置顶 → 点选」的动线对低频操作完全够用；相比之下 N2/N10 每天都在用会话列表空间换面板直达性，N4/N7 把动线拆到顶部反而更绕。
4. **可扩展性与演进余地**：面板从 10 涨到 30+，N1 只是浮层滚动区变长；高频用户可后续叠加 hover 直达（120ms 开/300ms 收）；若未来要更强的检索，浮层内可平滑融入 N3 的模糊匹配或 N10 的分类 chips，不需要推翻布局骨架。

**落地提醒**：① 必须先把 `SlotOutlet` panel 槽的 `activeIdx` 上提为受控状态（或经事件驱动），这是所有方案共同的第 0 步；② 入口按钮用「当前面板 icon + 名称 + ▾」的明确文案弥补发现性短板，首次进入可给一次性引导；③ 浮层打开时对消息流做半透明让位或保持浮层不越过 sidebar 右缘，减轻遮挡感；④ 移动端 ≤768px 走现有 `setDrawer('sidebar')` 抽屉 + 浮层改全宽底部弹层，复用 `.drawer-mask` 与 body 锁滚动逻辑。
