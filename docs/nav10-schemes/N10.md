# N10 · 混合：搜索 + 分类 chips + 紧凑列表（Hybrid Filter)

> 代号 N10。核心交互：左侧栏面板段 = 顶部搜索框 + 分类 chips 横向滚动条（单选或多选叠加过滤）+ 下方按当前过滤条件呈现的紧凑列表。它是 ToolSwitcher「搜索 + 分组」思想从浮层搬到常驻栏，并把分组从「硬编码 pinned/overflow 两层」升级为「用户可控的 chips 多维过滤」。

---

## 1. 交互结构图（文字图）

```
┌─ 左侧栏（240px，面板段）──────────────────┐
│  ⊞ 面板                                    │
│  ─────────────────────────────            │
│  🔍 搜索面板…                              │
│  ─────────────────────────────            │
│  分类 chips（横向滚动，可多选叠加）        │
│  [全部] [上下文] [运行] [集成] [开发] [系统]│
│  ─────────────────────────────            │
│  紧凑列表（按组小标题分节，可滚动）        │
│  ─ 上下文 ──────────────                   │
│   [icon] 文件                    active    │
│   [icon] 浏览器                            │
│  ─ 运行 ───────────────                   │
│   [icon] 终端                              │
│   [icon] AI 控制台                         │
│  ─ 集成 ───────────────                   │
│   [icon] 集成面板                          │
│  ─ 开发 ───────────────                   │
│   [icon] 开发者                            │
│   [icon] 示例插件                          │
│  ─────────────────────────────            │
│  （下方接会话列表）                        │
└───────────────────────────────────────────┘

chips 交互状态机：
  「全部」为默认单选项；
  点击分类 chip → 进入多选模式（「全部」取消）；
  多选 = OR 过滤（命中任一所选分类即保留）；
  再点已选 chip → 取消；全部取消 → 回到「全部」。
  chips 溢出时横向滚动 + 右缘渐隐遮罩提示可滚。
```

事件顺序：
1. `query` 输入（受控）→ `onQueryChange`；
2. `selectedCats: Set<CategoryId>` 变化 → 与 `query` 一起进 `useMemo` 计算过滤结果；
3. 过滤结果按 `group` 分组渲染；组标题行右侧显示该组命中数；
4. 点击列表项 → `onSelect(panelId)`（不关闭任何东西，因为是常驻栏）；
5. 空结果时渲染 `panel-hybrid-empty`（「没有匹配结果」+「清除筛选」按钮）。

## 3. 10+ 面板时的表现与数据流

- **过滤而非罗列**：面板越多，chips 的价值越大——用户先缩范围再浏览，列表长度始终 ≈ 单组面板数（通常 2~5 个），而非全量。
- **数据流（单向）**：
  1. `panels: ToolSwitcherItem[]`（含 `group: ToolGroupId`，分类轴直接复用 ToolSwitcher 的 `getToolGroup`，无需新增数据）；
  2. 状态：`query: string`、`selectedCats: Set<ToolGroupId>`（空集 = 全部）；
  3. `useMemo` 计算 `visible = panels.filter(p => (selectedCats.size===0 || selectedCats.has(p.group)) && match(p, query))`；
  4. `groupBy(visible)` → `{ context: [...], run: [...], ... }` 按固定组序输出；组内保持注册序；
  5. 搜索与 chips 是 AND 关系（先按分类缩域，再在域内做文本匹配）；`match` 规则与 ToolSwitcher 一致（`label description group` 小写 includes）；
  6. 选中面板 `activeId` 由外部布局状态下发，组件内不持有激活权（唯一权威在会话/布局 store）。
- **性能**：50 个面板 = 一次 filter + 分组，纯内存计算；列表无需虚拟化（50 行 DOM 可接受），>100 时再上 `content-visibility: auto`。
- **chips 记忆**：可将 `selectedCats` 持久化（key `polaris.panelFilters`），重进应用恢复上次过滤视图；但 `query` 不持久化。

## 4. 优缺点

**优点**
1. 三种检索方式叠加（文本搜索 + 分类过滤 + 分组浏览），是 10 方案里信息找回能力最强的组合；
2. 分类轴直接复用 ToolSwitcher 的 `ToolGroupId`，前后端与插件注册零改造；
3. 常驻列表 + 组标题让「还有哪些面板」始终可见，发现性优于 N8/N9 的隐藏长尾；
4. chips 多选 OR 过滤表达力强（如同时看「运行+开发」）。

**缺点**
1. 三层结构（搜索/chips/列表）占垂直空间，左侧栏面板段起始高度比 N1/N8 大，可能挤压会话列表；
2. 多选 chips 与「全部」的互斥、清空回退等状态机需要仔细处理，交互细节多；
3. 面板分类若与用户心智不符（如某插件被归到「系统」），chips 反而增加一次试错；分类语义需在注册时把关；
4. 相比 ToolSwitcher 少了「临时浮层」的轻量感，视觉上更「重」。

## 5. 与 ToolSwitcher 的异同对照表

| 维度 | ToolSwitcher（参考实现） | N10 混合过滤 |
|---|---|---|
| 存在形态 | 浮层（临时打开） | 常驻侧栏面板段 |
| 搜索 | 搜索行 | 搜索行（同构，另加清除按钮） |
| 分类机制 | 硬编码两层：pinned grid + overflow grid | chips 多选过滤 + 动态分组列表 |
| 分类数据 | `getToolGroup` / `PINNED_LEFT_PANEL_TYPES` | 复用同一 `ToolGroupId` 分类轴 |
| 列表形态 | 4 列 grid + 3 列 grid | 单列紧凑行 + 组小标题 |
| 打开/关闭 | 有浮层生命周期（mousedown 外部/Escape） | 无，常驻；无关闭语义 |
| 底栏 | 当前侧栏 + 关闭侧栏 | 保留同构底栏 |
| 状态管理 | `query` 局部 state | `query` + `selectedCats`（可持久化） |
| 空态 | 「没有匹配结果」 | 同左 + 「清除筛选」动作 |

## 6. 实施步骤清单

1. 实现 `PanelHybrid` 组件骨架（header/search/chips/scroll/footer 五段），class 按上文命名；
2. 定义过滤状态：`query`、`selectedCats: Set<ToolGroupId>`；chips 点击处理「全部 ↔ 多选」互斥逻辑（选「全部」清空其他；选任一分类时移除「全部」；清空自动回「全部」）；
3. 实现 `filterAndGroup(panels, query, selectedCats)` 纯函数（便于 vitest 单测）；
4. 渲染 chips 行：横向 `overflow-x-auto`、`scrollbar-none`、右缘渐隐 fade；`aria-pressed` 表达选中态；
5. 渲染分组列表：组标题 + 计数；行结构 icon+label+active 徽标；空组不渲染；
6. 空态与「清除筛选」：一键重置 `query=''`、`selectedCats=∅`；
7. 底栏接入当前激活面板 label 与关闭侧栏回调（对齐 ToolSwitcher footer 语义）；
8. 可选增强：`selectedCats` 持久化到 localStorage；chips 键盘左右键导航；
9. 自测清单：搜索与 chips 叠加（AND）正确、多选 OR 正确、「全部」互斥、清除筛选、仅一个分组时隐藏组标题或保留、移动端 ≤768px 抽屉态下 chips 可横滚、`content-visibility` 对 100+ 面板渲染耗时。
