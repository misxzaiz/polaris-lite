# N7 · 分屏 Tab 条（左侧面板导航方案）

> 对应总纲：`docs/nav10-schemes/brief-nav10.md` 路线 N7。
> 参考实现：`D:\space\base\Polaris\src\components\Layout\ToolSwitcher.tsx`（视觉语言：搜索行、grid、底栏、三级文字色）、`src/core/SlotLayout.tsx`（四槽壳与移动端抽屉状态机）。
> 与现状（`SlotOutlet` 的 `slot-tabbar` 平铺）的区别：现状 Tab 在**右侧 panel 槽内部**平铺、多了就挤压；N7 把 Tab 条移到**左侧栏上部横向滚动**，并在 Tab 条下方增加一个「当前面板内容预览」分屏区，Tab 多时靠横滚 + 末尾「更多」下拉消化。

---

## 0. 一句话方案

左侧栏分为上下两段：**上段是横向可滚动的面板 Tab 条**（chip 排布，等高不换行，溢出时末尾出现「⋮ 更多」下拉），**下段是当前 Tab 对应面板的预览区**（标题 + 描述 + 关键状态 + 打开按钮）。Tab 条负责「切换与可达」，预览区负责「不用跳转也能看清当前面板是什么」；会话列表压缩到最底部。

## 2. 状态模型与数据流

### 2.1 状态所有权

| 状态 | 所有者 | 说明 |
|---|---|---|
| `activePanelId` | shell 级 context（单一权威） | Tab 激活态、预览区、右侧 panel 槽三方消费 |
| `visibleCount` | Tab 条组件（由容器宽度测量派生） | 可见 Tab 数 = f(容器宽)；溢出者进「⋮ 更多」 |
| `moreOpen` | Tab 条组件 | ⋮ 下拉开合 |
| `query` | ⋮ 下拉内部 | 下拉内搜索过滤 |
| 面板列表 | `host.slots.list('panel')`，`(order ?? 0)` 稳定排序 | 纯展示层消费，不改注册表 |

### 2.2 「预览即内容」的两档模式（本方案的关键设计决策）

N7 的 Tab 条在左侧，而 panel 槽在右侧，存在「点 Tab 后右侧是否立即切换」的两种档位：

- **档位 A · 预览轻量（默认）**：点 Tab 只更新左侧预览区（名称/描述/状态 chips），右侧 panel 槽保持原面板；点预览区「在右侧打开 →」才真正切换 `activePanelId`。适合面板内容重（如图表、终端）的场景，避免误点即重渲染。
- **档位 B · 直切**：点 Tab 即 `setActivePanelId(X)`，预览区仅作为该面板的摘要说明与面板内容同屏呈现（左侧看摘要、右侧看内容）。适合面板内容轻的场景。

原型通过一个开关（预览区底部的「直切模式」checkbox）演示两档；宿主落地时可作为用户偏好存 `cap.config`。

### 2.3 事件流

```
slots.list('panel') 变化
  → Tab 条重排（order 稳定排序）
  → 重测容器宽 → 重算 visibleCount → 溢出者进 ⋮ 收纳区
  → 若 activePanelId 被卸载：回落列表第一个面板

窗口 resize
  → ResizeObserver 重算 visibleCount（带 ±1 滞回防抖动，同 S1 §6.2 经验）
  → 激活 Tab 始终保持在可见区或 ⋮ badge 提示

点击 Tab X（档位 B）
  → setActivePanelId(X) → panel 槽渲染 X → 预览区摘要同步 X

点击 ⋮ 下拉内面板 Y
  → 同上切换 Y；下拉关闭；若 Y 属溢出区，⋮ 挂 badge
```

### 2.4 持久化

- key：`polaris.tabstrip.prefs.v1`，内容 `{ active, directSwitch: boolean }`。
- 原型写 localStorage；宿主落地走 `cap.config`。

## 4. 10+ 面板时的表现与数据流

**表现**：

1. **横向收纳**：Tab 条单行横滚；容器宽约 244px（260 - padding），每个 chip 约 56~88px，可见 3~4 个；其余进「⋮ 更多」下拉。`visibleCount` 由 `ResizeObserver` 实测（chip 宽不等长，不能按固定个数估算），带 ±1 滞回防临界抖动。
2. **⋮ 下拉承担罗列**：面板 12~20 个时，下拉内用「搜索行 + 单列紧凑列表」承载全量（对齐 ToolSwitcher 的搜索 + 溢出列表，只是从 3 列 grid 改单列以适配 240px 宽）；激活项在下拉内高亮，⋮ 挂 badge。
3. **激活可达性保证**：激活 Tab 若被收纳进 ⋮，下拉内高亮 + badge 提示；打开下拉时激活项 `scrollIntoView({block:'nearest'})`。
4. **预览区不随数量膨胀**：预览区高度固定（约 120px），只展示当前 Tab 的摘要；面板增多不影响它，会话列表压缩量可控。
5. **极端情况（>24 面板）**：下拉内搜索成为主路径（同 ToolSwitcher 的「多则搜」逻辑）；Tab 条保持只放最高频的 3~4 个，用户可把不常用的全部留在收纳区。

**数据流**（一次典型切换，档位 B 直切）：

```
点击 ⋮ → 下拉展开 → 搜索 "log"
  → query 过滤收纳区 → 命中「日志」→ 点击
  → setActivePanelId('logs')
  → Tab 条：logs 若在可见区则 .active + scrollIntoView；
    若在收纳区则保持隐藏、⋮ 挂 badge
  → 预览区渲染 logs 摘要（icon/名称/描述/chips）
  → panel 槽只渲染 logs（受控激活）
  → 下拉关闭 → 持久化 { active:'logs', directSwitch:true }
```

**移动端（≤768px）**：

- Tab 条固定在 `.shell-topbar` 下方（`position:sticky; top:topbar高度`），横滚全宽；预览区并入 sidebar 抽屉顶部，点 Tab 选中后 `setDrawer('none')`。
- ⋮ 下拉改为底部 action-sheet（对齐 S1/N5 的移动端策略）：`bottom:0; width:100vw; max-height:60vh; border-radius:12px 12px 0 0; padding-bottom:env(safe-area-inset-bottom)`。
- ≤360px：Tab chip 只显示图标（隐藏文字），预览区 desc 折叠为一行。

## 5. 优缺点

### 优点

1. **切换路径最短**：Tab 一次点击直达（档位 B），交互成本与现状 `slot-tabbar` 持平，但横滚 + 收纳结构性地解决了挤压问题（A、B 维度兼顾）。
2. **预览区降低误切成本**：重内容面板（终端/图表）不必「点开才知道」，预览区先给摘要；档位 A 下点 Tab 零渲染成本，适合面板多的场景。
3. **结构改动小**：Tab 条仍在 sidebar 槽内部（只是从右侧 panel 槽移过来 + 横向化），`.shell-sidebar` 的纵向 flex 结构、`setDrawer` 状态机都不用动；比 N5（加列）N6（递归树）落地面小。
4. **视觉延续性好**：Tab chip、⋮ 下拉、搜索行、底栏全部对齐 ToolSwitcher 的语言（`bg-elevated`、chip 圆角、三级文字色），且用户对「顶部 Tab」心智零学习。

### 缺点

1. **可见 Tab 数太少**：260px 宽侧栏只放得下 3~4 个 chip，高频面板超过 4 个时大部分入口都藏在 ⋮ 里，「直达」优势衰减（对比 N2 常驻列表全部可见）。
2. **横向滚动发现性差**：横滚条本身不显眼，用户可能不知道右侧还有更多 Tab；需要渐隐 mask + ⋮ badge 双重提示，仍可能被忽略。
3. **预览区占用固定高度**：侧栏纵向被 Tab 条(≈42px) + 预览区(≈120px) 占去约 162px，会话列表可视条目减少；对会话密集型用户不友好。
4. **双档位增加状态复杂度**：档位 A/B 的切换语义（点 Tab 是否切右侧）需要清晰的默认值与持久化，否则会出现「点了没反应（A 档只改预览）」的困惑；原型必须把两档都做出来并给默认直切。

## 6. 与 ToolSwitcher 的异同对照表

| 维度 | ToolSwitcher（Polaris 顶部） | N7 分屏 Tab 条 |
|---|---|---|
| 形态 | 点击/hover 弹出的浮层（fixed 360px） | 常驻侧栏上段的**横向 Tab 条 + 预览分屏** |
| 入口组织 | 置顶 4 列 grid + 溢出 3 列 grid | 可见 3~4 个 chip + ⋮ 收纳下拉（单列列表） |
| 触发 | 触发按钮 click / hover 120ms 开 300ms 收 | Tab 直接点击；⋮ 点击开下拉；Esc/外点关下拉 |
| 搜索行 | 有：过滤 label/description/group | 有：在 ⋮ 下拉内，过滤收纳区面板（样式同规格） |
| 底栏 | 「当前侧栏： X + 关闭」 | 「当前侧栏： X」放进 ⋮ 下拉底部；预览区另有「在右侧打开」主按钮 |
| 激活态 | `item.active` → `bg-primary/10 text-primary` | chip `.active` 同款 accent-soft 底 + accent 字 + 边框 |
| 溢出语义 | overflowItems 常驻浮层内展示 | 溢出 Tab **隐藏**（visibility）进 ⋮，需开下拉才能见 |
| 定位 | anchorRef 锚定按钮下方 + clamp | ⋮ 下拉 absolute 锚定 ⋮ 按钮右下，无 JS 定位计算 |
| 独有部分 | 无（纯选择器） | **预览分屏区**：当前面板摘要 + 直切/预览双档位开关 |
| 数据来源 | `ToolSwitcherItem[]` props | `host.slots.list('panel')` + manifest 摘要 |
| 面板多时 | 一屏罗列 + 搜索兜底 | 横滚 + 收纳 + 下拉内搜索；可见入口更少但每次点击成本更低 |
