# N4 · 顶部横滚条（面板导航移到消息区顶部的横向 chip 滚动条）

> 参考对象：Polaris ToolSwitcher 的**视觉语言**（bg-elevated 底、圆角 chip、is-active 主色高亮、搜索弹层兜底），但**空间位置完全不同**——导航从左侧栏移到消息区（stream 槽）顶部，横向滚动排布。
> 对应总纲表 N4：面板导航放消息区顶部横向滚动条（chip 排布），左侧栏只留会话列表。

---

## 1. 交互结构图（文字图）

```
┌──────────┬──────────────────────────────┬───────┐
│ sidebar  │   stream                     │ panel │
│          │ ┌──────────────────────────┐ │       │
│ 品牌     │ │ panel-chip-bar（横滚）   │ │       │
│          │ │ [文件✓][Git][终端][浏览器]│→ 横向滚动│
│ ──────── │ │ [模型管理][集成][开发者]…│ │       │
│          │ └──────────────────────────┘ │       │
│ 会话列表 │   消息流                     │ 面板  │
│          │   …                          │       │
│ (完整空  │                              │       │
│  间恢复) │                              │       │
│          │ ┌──────────────────────────┐ │       │
│          │ │ 输入区                   │ │       │
│          │ └──────────────────────────┘ │       │
└──────────┴──────────────────────────────┴───────┘

结构关系：
- panel-chip-bar 插在 stream 槽顶部（消息流上方、输入区之外），属于「导航条」不属于消息内容。
- 左侧 sidebar 不再有任何面板导航（N4 的定义性特征），只留品牌 + 会话列表。
- 面板超过可视宽度 → chip 条横向滚动（overflow-x:auto），当前选中 chip 自动 scrollIntoView。

事件顺序：
[面板注册/注销] → registry → chips 重算
[点击 .panel-chip]
  → onSelect(panelId) → activePanelId 更新
  → chip 加 .is-active；panel 槽切换；chip scrollIntoView({inline:'nearest'})
[chip 溢出]
  → 左右可拖动/滚轮横滚；可选两端渐隐遮罩提示还有更多
[面板过多仍找不到]
  → 条尾「▸▸ 更多」按钮 → 弹出 ToolSwitcher 式搜索浮层兜底（复用 N1 浮层，含搜索行/置顶 grid/底栏）
```

## 3. 10+ 面板时的表现与数据流

- **数据源**：仍来自 `slotRegistry.list('panel')` → `PanelNavItem[]`（与 N1~N3 共用 `panelNav.ts`），渲染为 chip 数组。
- **10+ 面板的空间表现（本方案的立身之本）**：
  1. chip 条**横向消化数量**：每个 chip 固定高度（~28px）但宽度按内容自适应，10+ 面板表现为 chip 条变长，超出 `shell-main` 宽度即横向滚动，**完全不消耗纵向空间**，消息流高度不受面板数影响；
  2. 当前激活 chip 用 `scrollIntoView({ inline: 'nearest', behavior: 'smooth' })` 保证切换后始终可见；
  3. 视觉提示：chip 条两端各加 12px 渐隐 mask（`mask-image: linear-gradient(...)`），暗示两侧还有内容；
  4. 超过 ~12 个时（阈值可配）条尾出现「▸▸ +n」按钮，点击弹出 ToolSwitcher 式搜索浮层（N1 的浮层整体复用），兜底「搜索直达 + 置顶 + 全量列表」能力；
  5. 滚轮横滚支持：chip 轨道监听 `wheel`，`deltaY` 转 `scrollLeft`（桌面常见习惯）。
- **数据流**：`registry → chips；点击 chip → onSelect → activePanelId → is-active 迁移 + panel 槽切换 + scrollIntoView；「更多」浮层内部 query → filteredItems（同 N1）`。sidebar 槽零改动，会话列表数据流与面板导航完全解耦——这是 N4 架构上最大的收益。
- **移动端**：≤768px 时 chip 条天然适配（横向滚动是移动端习惯），可整条移入 topbar 下方；「更多」浮层改全宽底部抽屉。

## 4. 优缺点

**优点**
1. **彻底解放左侧栏**：sidebar 只剩会话列表，长会话场景的可用空间最大化；这是唯一一个「会话列表零挤压」的左侧不动方案。
2. **面板数量不占纵向空间**：chip 横向滚动消化数量，配合「更多」浮层兜底，10+ 甚至 30+ 面板都不产生纵向压力。
3. **符合消息区顶部导航的常见心智**：类似浏览器 tab 条 / IDE 顶部工具条，位置直觉；移动端横滚天然友好。
4. **架构解耦干净**：面板导航与 sidebar 槽（会话列表插件）完全分离，两边插件互不感知，符合 polaris-lite「槽位隔离」的设计取向。

**缺点**
1. **横向可发现性差**：溢出的 chip 藏在滚动条后，用户不知道右侧还有面板；必须依赖渐隐 mask + 「+n」提示 + 浮层兜底三件套补偿。
2. **挤压消息流纵向空间**：chip 条本身占 ~40px 高度；对「消息流一屏最大化」的目标是净损失（N1/N3 只在切换瞬间出现浮层，常态不占）。
3. **面板切换动线变长**：面板在顶部、会话在左侧、内容在右侧，切换面板时视线要横跳；且 chip 条与右侧 panel 区的对应关系不如左侧导航直观。
4. **需要维护两套交互**：chip 直选 + 浮层兜底并存，浮层打开时 chip 条的高亮、浮层内 is-active 与外部 activePanel 的同步都要处理，状态面比纯 chip 或纯浮层都大。

## 5. 与 ToolSwitcher 的异同对照表

| 维度 | Polaris ToolSwitcher | N4 方案 |
|---|---|---|
| 位置 | ActivityBar 上方 fixed 浮层 | stream 槽顶部常驻横滚条 + 条尾浮层兜底 |
| 常态可见性 | 关闭时不可见 | chip 条常驻可见；全量列表仍藏于浮层 |
| 布局方向 | 纵向 grid（4 列置顶 + 3 列溢出） | 横向 chip 排布 + overflow-x 滚动 |
| 搜索行 | 浮层内常驻 | 仅在「更多」浮层内（兜底时才出现） |
| 置顶 4 列 grid | 有 | 浮层内保留；chip 条上以「排前」表达置顶 |
| 溢出 3 列 grid | 有 | 浮层内保留；chip 条上以横滚表达溢出 |
| 底栏「当前侧栏」 | 有 | 浮层内保留；chip 条以 is-active 表达当前 |
| is-active 语义 | 浮层选项高亮 | chip 常驻高亮 + 自动滚入视野 |
| 对 sidebar 的影响 | 无（浮层覆盖） | 无（sidebar 完全不动，这是本方案定义） |
| 数据源 | toolSwitcherData + 面板 | slotRegistry panel 槽（共用适配层） |
| 视觉 token | bg-elevated / 圆角 / 主色高亮 | 沿用（chip 圆角 999px、accent-soft 激活） |

## 6. 实施步骤清单

1. **数据适配**：复用 `panelNav.ts`；chips 按置顶优先排序（置顶集合语义同 ToolSwitcher 的 `PINNED_LEFT_PANEL_TYPES`）。
2. **chip 条组件**：新建 `src/core/PanelChipBar.tsx`——`panel-chip-bar > panel-chip-track > panel-chip*` + 条尾 `panel-chip-more`；实现点击选中、`scrollIntoView({inline:'nearest'})`、wheel 横滚、两端渐隐 mask。
3. **兜底浮层**：复用 N1 的 `PanelSwitcher.tsx`（搜索行/置顶 grid/溢出 grid/底栏完整保留），由 `panel-chip-more` 触发打开；浮层内 `is-active` 与 `activePanelId` 同源。
4. **布局接线**：在 `SlotLayout` 的 `shell-main` 内、`shell-stream` 之前插入 chip 条；确认 `shell-stream` 的 `overflow:hidden` 与 flex 高度分配不被破坏（chip 条 `flex:0 0 auto`）。
5. **sidebar 还原**：确认 sidebar 槽内不再渲染任何面板导航组件，会话列表恢复完整空间。
6. **样式**：`styles.css` 增加 `.panel-chip-bar/.panel-chip-track/.panel-chip/.panel-chip-more`；chip 用 CSS 变量；≤768px 时 chip 条移至 topbar 下方、隐藏 more-count 之外的多余装饰。
7. **验证**：12 个模拟面板——chip 横滚、激活 chip 自动滚入视野、渐隐遮罩可见、点击「+n」弹浮层、浮层搜索切面板后 chip 高亮同步、消息流高度不被面板数影响；`tsc` 通过。
