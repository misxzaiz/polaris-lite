规划要点

核心矛盾：窄屏一行塞了 5 个控件，chip 与主按钮不同构；工具调用流式平铺占满消息区；次要状态没有收纳位。

A 档尺寸统一

  • 所有可点控件统一 40px 高（触摸目标基准），chip 不再用 22px 的独立尺度。
  • 主/次分层：主操作（发送/停止 + 附件）常驻输入行；工作区、信任模式、队列移入上拉面板。
  • 禁用态降级为幽灵样式，避免空输入时「排队」仍像主按钮。

B 档信息密度

  • 工具调用默认折叠为一条「工具调用 · N 项 · 耗时 / 有失败」，点开看详情。
  • 退出码仅非 0 时显示；成功卡片头部只留勾选 + 耗时。
  • 命令摘要去 grep 转义、按 token 截断，不再断在 \| 中间。

C 档上拉交互

  • 输入区顶部把手，上拉展开「助手面板」；点击把手可展开，不依赖隐藏手势。
  • 信任模式改为琥珀警示色——安全门槛降低的状态不该用绿色。
  • 舒适 / 紧凑两档作用于消息间距、卡片内边距、行高。
落地状态：已实施。A/B/C 三档均已进入 chat-lite 源码（BlockGroup / ToolCard / ChatInput / chat.css / chat-input.css），typecheck 与 148 项测试全绿。

一处与原型不同：原型画的「全屏展开编辑器」在落地时改为「就地增高」——项目插件 CSS 门禁禁止 position:fixed（会逃出窗格盖住分隔条/抽屉），宿主也无 overlay 能力。展开态把 textarea 增高到 36dvh（约 295px），仍是同一个输入框，草稿/IME/发送全部复用。

原型本身已加手机视口适配（≤640px 去外框铺满视口、控制条横滑）。
