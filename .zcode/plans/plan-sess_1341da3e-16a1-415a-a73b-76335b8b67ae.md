# 工具卡信息增强 + JSON 参数折叠 + 截图修复

## Context（诊断结论）

**问题 1：工具卡看不出操作了什么** — 三个叠加缺陷：
- `plugins/agent-loop/index.ts:794`：`command = String(parsed.command ?? '')` 只对 bash 有效；browser/ledger/files/MCP 等语义工具全是空串。
- `plugins/chat-lite/index.ts:334`：`command: inner.command ?? inner.argsJson` — 空串不是 nullish，argsJson 兜底永不触发 → 卡片摘要为空，只显示「完成」。
- `plugins/chat-lite/index.ts:355` tool.result 处理器不回填 `command`（agent-loop 明明在 tool.result 里发了 `browser <action>`）。
- 审批卡同样受害：browser 审批卡的命令 pre 是空白的。

**问题 2：JSON 参数不可见** — `ToolCardData` 根本没有存 argsJson 的字段（tool.card 事件带了，chat-lite 丢弃）。

**问题 3：截图消失** — 数据实证：11-20 15:34 后生产所有会话 0 个截图 artifact；浏览器调用 stdout 全是裸 `{ok:true}`（按现有任一版服务端代码都不可能）；html-preview 产物同期正常。**根因：生产 9825 前端半边与 server 半边版本错位** — 新 UI 半边的 `callBrowserApi` 解析 `{ok:true, result:{...}}` 包装，旧 server 半边返回平铺形状 → `json.result` 为空 → 字段全丢，且 `r.shotId` 取不到 → 截图 artifact 永不发出（文件却照常落盘）。当前仓库代码链路是对的，只差部署对齐 + 修一个双渲染 bug。

**问题 4（顺带发现）**：`plugins/chat-lite/BlockGroup.tsx:229` `processed.add({type:'artifact', card:a})` 新建了对象而非标记原块引用 → 截图会渲染两次（组内一次 + 尾部一次）。

## 改动

### 1. `plugins/agent-loop/tool-summary.ts`（新文件）
导出纯函数 `summarizeToolCall(name, argsJson) → { display, approvalKey }`：
- `display`（给人看，≤120 字符）：bash → 原命令；browser → `browser navigate → https://…` / `browser click "登录"` / `browser fill [selector] ← 值` / `browser press Enter` / `browser scroll ↓600` / `browser search "词" @bing` / `browser screenshot (整页)` / `browser wait selector .x` 等；ledger/files → `<family> <action> <path>`；render → `render <title>`；interactive → `interactive <kind>`；skill → `skill <name>`；MCP（`mcp__` 前缀）→ 去前缀工具名；无效 JSON → 工具名。
- `approvalKey`（给「总是允许该前缀」用，必须稳定）：bash → 原命令（**语义完全不变**）；browser → `browser <action>`（与现有 tool.result 前缀一致，动作级放行）；MCP → 工具名；其余 → `<family> <action>`。

### 2. `plugins/agent-loop/index.ts`
- L794-802 tool.card 发射处改用 `summarizeToolCall`（display 进 command 字段，argsJson 原样带上）。
- L885 `decideApproval(..., approvalKey)`；`tool.approval.required` 事件带 display（审批卡有内容可看）+ argsJson。
- browser 分支 L1071、generic exec L1112 的 tool.result 也用 display（终态卡片摘要更详细）。

### 3. `plugins/chat-lite/store.ts`
- `ToolCardData` 增加 `argsJson?: string`；`trimCard` 对 command/argsJson 同样做 16KB 裁剪。

### 4. `plugins/chat-lite/index.ts`
- tool.card 建块：`command: inner.command || inner.argsJson`（空串落到 argsJson），存 `argsJson`（16KB cap）。
- tool.result 补丁：`inner.command` 有值时回填 command。

### 5. `plugins/chat-lite/ToolCard.tsx` — JSON 折叠组件
- 新增 `ArgsBlock`：有 argsJson 且参数不含 `command` 键（自然排除 bash 避免重复）时渲染；默认折叠（一行预览 + chevron），点开 pretty JSON（`JSON.stringify(parse, null, 2)`）放 `tc-args` pre（max-height 滚动，复用 tc-cmd 模式）；解析失败显示原文。
- 展开体顺序：命令 → 参数（可折叠）→ 输出 → 退出码；`hasBody` 计入 argsJson。

### 6. `plugins/chat-lite/chat.css`
- `.tc-args`（mono、max-height 16rem、thin scrollbar）、`.tc-args-toggle` 行样式，沿用现有 tc-* 视觉。

### 7. `plugins/chat-lite/BlockGroup.tsx` — 双渲染修复
- 建 `callId → artifact 原块` Map，`processed` 标记回原块引用（修 L229）。`hasArtifactTool` 正则保留（兼容旧会话 shotId callId）。

### 8. 测试 `tests/agent-loop-compat.test.mjs`
- 直接 import `../plugins/agent-loop/tool-summary.ts`（仓库已有 `--experimental-strip-types` 导入先例）：browser 全动作 display/approvalKey 形态、bash 透传不变、MCP/ledger/files 形态、approvalKey 稳定性、超长截断、非法 JSON 兜底。
